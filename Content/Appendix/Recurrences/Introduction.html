Solving Recurrence Relations

Definitions and Terminology

A recurrence relation defines the terms of a sequence by referring back to earlier terms of the same sequence. More formally, a recurrence relation is a formula that defines \(a_n\) in terms of one or more earlier values, such as \(a_{n-1}\), \(a_{n-2}\), or, more generally, \(a_i\) for values of \(i<n\). To determine a particular sequence, we also need enough starting values, called initial conditions or base cases.

Remark

Recurrence relations are often written using either sequence notation, such as \(a_n\), or function notation, such as \(a(n)\). In algorithm analysis, function notation is especially common, as in \(T(n)\) for the running time on an input of size \(n\). For this section, you can treat these notations as essentially equivalent.

Example 1

We previously saw that factorials can be defined by \(0!=1\), and if \(n>0\), \[ n!=n\cdot(n-1)!. \] This is a recurrence relation for the sequence \(n!\). The recursive rule is \(n!=n\cdot(n-1)!\), and the initial condition is \(0!=1\).

Similarly, the Fibonacci sequence is defined by \(f_0=f_1=1\), and for \(n>1\), \[ f_n=f_{n-1}+f_{n-2}. \] This is a recurrence relation for the sequence of Fibonacci numbers. The recursive rule uses two earlier values, so we need two initial conditions.

Example 2

Each of the following is a recurrence relation.

\[ \begin{aligned} t_n &= n\cdot t_{n-1} + 4\cdot t_{n-3}\\ r_n &= r_{n/2}+1\\ a_n &= a_{n-1}+2\cdot a_{n-2}+3\cdot a_{n-3}+4\cdot a_{n-4}\\ p_n &= p_{n-1}\cdot p_{n-2}\\ s_n &= s_{n-3} + n^2 - 4 n + 32 \end{aligned} \]

We have not given any initial conditions for these recurrence relations. Without initial conditions, we cannot compute particular values. We also cannot solve the recurrence relation uniquely.

When recurrence relations are used to analyze algorithms, it is useful to separate the terms into two categories: recursive terms and nonrecursive terms. Recursive terms refer to earlier values of the same sequence. Nonrecursive terms do not.

For example, in the recurrence \[ s_n=s_{n-3}+n^2-4n+32, \] the recursive term is \(s_{n-3}\), and the nonrecursive term is \(n^2-4n+32\).

In computer science, recurrence relations are commonly used to analyze recursive algorithms. A recursive call usually produces a recursive term in the recurrence relation, while the other work done by the method produces the nonrecursive term. We will not get too technical yet, but the following example shows the basic idea.

Example 3

How many multiplications are required to compute \(n!\) using the following recursive factorial algorithm?

int factorial(int n) {
  if (n <= 0) {
    return 1;
  } else {
    return n * factorial(n - 1);
  }
}

Solution

Let \(M_n\) be the number of multiplications needed to compute \(n!\) using this algorithm. If \(n=0\), the algorithm returns \(1\) and performs no multiplications, so \(M_0=0\). If \(n>0\), the algorithm performs one multiplication and makes one recursive call to factorial(n - 1). By the definition of \(M_n\), that recursive call uses \(M_{n-1}\) multiplications. Therefore,

\[ M_n= \begin{cases} 0, & n=0,\\ M_{n-1}+1, & n>0. \end{cases} \]

These definitions give us the language we need to talk about recurrence relations. Next we will focus on what it means to solve one and why closed-form expressions are useful.

Solving Recurrence Relations

Given a recurrence relation for \(a_n\), we usually cannot just plug in \(n\) and immediately get an answer. For instance, if \(a_n=n\cdot a_{n-1}\) and \(a_1=1\), what is \(a_{100}\)? The most direct approach is to compute \(a_2, a_3,\ldots,a_{99}\), and then finally \(a_{100}\). This is why solving recurrence relations is important. Solving a recurrence relation means finding a closed form expression: a formula for \(a_n\) that depends directly on \(n\), rather than on earlier terms of the same sequence.

Example 4

In the factorial example, we found the recurrence \[ M_n= \begin{cases} 0, & n=0,\\ M_{n-1}+1, & n>0. \end{cases} \] This recurrence has the solution \(M_n=n\).

To prove this, first check that the formula agrees with the base case: \(M_0=0\). Now assume \(M_k=k\) for some \(k\geq 0\). Then

\[ M_{k+1}=M_k+1=k+1. \]

Therefore, if the formula is correct for \(k\), it is also correct for \(k+1\). By induction, \(M_n=n\) for all \(n\geq 0\).

This example reinforces how recurrence relations arise when analyzing recursive algorithms. Recursive calls contribute the recursive terms, while the other work done by the method contributes the nonrecursive terms. The recurrence in this example was especially easy to solve, but most recurrences require more systematic techniques. Before introducing those techniques, let's look at one more simple example of setting up a recurrence from an algorithm.

Example 5

Consider the recursive binary search algorithm:

int binarySearch(int[] a, int left, int right, int val) {
  if (right >= left) {
    int middle = (left + right) / 2;

    if (val == a[middle]) {
      return middle;
    } else if (val < a[middle]) {
      return binarySearch(a, left, middle - 1, val);
    } else {
      return binarySearch(a, middle + 1, right, val);
    }
  } else {
    return -1;
  }
}

Find a recurrence relation for the worst-case running time of binarySearch.

Solution

Let \(T_n\) be the worst-case running time of binarySearch on an array segment of size \(n\). Aside from the recursive call, the algorithm does only a constant amount of work: it computes the middle index, makes a few comparisons, and returns a value. In the worst case, it makes one recursive call on approximately half of the current array segment. Therefore,

\[ T_n=T_{n/2}+1. \]

Remark

Technically, the recursive call is on either \(\lfloor n/2\rfloor\) or \(\lceil n/2\rceil\) elements, depending on the size of the current array segment and which side is searched. For asymptotic analysis, this distinction usually does not affect the final answer, so we often write \(T_{n/2}\) for simplicity.

As a base case, we can use \(T_0=1\), since an empty array segment causes the algorithm to return \(-1\) after constant work.

We will discuss using recurrence relations to analyze recursive algorithms in more detail in the section Analyzing Recursive Algorithms. However, our immediate focus is on solving recurrence relations. There is no single method that works well for every recurrence. In the next few sections we will study four common techniques: the substitution method, the iteration method, the Master Theorem, and the characteristic equation method for linear recurrences.

Question 2

What does it mean to solve a recurrence relation?

It means to find a closed-form expression for it. In other words, the answer should describe the sequence directly rather than recursively.

From this point on, we will often use function notation, such as \(T(n)\), especially when discussing running times, since this is the standard notation in algorithm analysis. However, we will continue to use sequence notation, such as \(a_n\), when discussing sequences in general.
