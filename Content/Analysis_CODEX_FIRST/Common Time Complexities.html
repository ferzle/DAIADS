Common Time Complexities

Overview

Algorithm analysis often produces the same families of running times again and again. Recognizing these complexity classes helps you read code, compare algorithms, and set expectations about what input sizes are realistic.

This page follows the LaTeX chapter's list of common classes, but places them in the DAIADS context with code patterns and algorithm examples.

Complexity Classes

Class Typical notation Common source Examples
Constant \(\Theta(1)\) A fixed amount of work independent of \(n\) Array indexing; comparing two numbers; stack push in a typical implementation
Logarithmic \(\Theta(\log n)\) Repeatedly discarding a constant fraction of the remaining input Binary search; balanced search tree operations
Linear \(\Theta(n)\) Scanning all input items a constant number of times Sequential search worst case; finding a maximum
Linearithmic \(\Theta(n\log n)\) Many divide-and-conquer algorithms with linear work per level Merge sort; heapsort; average-case quicksort
Quadratic \(\Theta(n^2)\) Many all-pairs comparisons or two \(n\)-sized nested loops Selection sort; many simple duplicate checks
Polynomial \(\Theta(n^k)\) for constant \(k\) A fixed power of the input size Standard matrix multiplication is \(\Theta(n^3)\)
Exponential \(\Theta(k^n)\) for constant \(k>1\) Trying all subsets, assignments, or branching choices Brute-force subset generation; some backtracking worst cases

Constant and Linear

Constant time does not mean the code literally takes exactly the same number of nanoseconds for every input. It means there is a fixed upper bound on the amount of work that does not grow with \(n\).

Constant 
int fifthElement(int[] a) {
    return a[4];
}

The method does one array access and one return. The work does not grow with the array length, so it is \(\Theta(1)\), assuming index 4 is valid.

Still Constant 
int partialSum(int[] a) {
    int sum = 0;
    for (int i = 0; i < 42; i++) {
        sum += a[i];
    }
    return sum;
}

The loop runs 42 times no matter how large the input array is. Since 42 is a constant, the method is \(\Theta(1)\), again assuming the array has enough elements.

Linear 
int sumFirstN(int n) {
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        sum += i;
    }
    return sum;
}

The loop runs \(n\) times and does constant work each time, so the running time is \(\Theta(n)\).

Logarithmic and \(n\log n\)

Logarithmic algorithms usually appear when each step removes a constant fraction of the remaining input. Binary search removes about half of the remaining array each iteration, so its worst-case running time is \(\Theta(\log n)\).

Many \(n\log n\) algorithms do linear work across each level of a logarithmic-depth process. Merge sort is the classic example: each level of recursion processes all \(n\) elements during merging, and there are \(\log n\) levels.

Quadratic and Polynomial

Quadratic algorithms often arise from all-pairs work. If every item must be compared with every other item, there are on the order of \(n^2\) pairs. A simple double loop with \(n\) iterations in each loop is also usually quadratic. 

int[][] computeSums(int[] a) {
    int n = a.length;
    int[][] sums = new int[n][n];
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            sums[i][j] = a[i] + a[j];
        }
    }
    return sums;
}

The assignment inside the inner loop runs \(n\cdot n=n^2\) times, so the algorithm is \(\Theta(n^2)\).

More generally, a polynomial-time algorithm has time \(\Theta(n^k)\) for some constant \(k\). Linear and quadratic algorithms are special cases. In many theoretical contexts, "efficient" means polynomial time, though in practice a high-degree polynomial may still be too slow.

Exponential

Exponential algorithms usually appear when the algorithm branches into many possibilities: all subsets, all binary strings, all assignments, or all choices in a search tree. There are \(2^n\) binary strings of length \(n\), so an algorithm that lists them all must take at least \(\Theta(2^n)\) time just to produce the output.

Exponential algorithms are usually practical only for small inputs unless pruning, approximation, randomness, or problem-specific structure changes the effective search.

Faster Growth Means Slower Algorithms

The language can be confusing. A function that grows faster represents more work, so it usually represents a slower algorithm for large inputs. If algorithm \(A\) runs in \(\Theta(n\log n)\) time and algorithm \(B\) runs in \(\Theta(n^2)\) time for the same problem, then \(A\) usually scales better because \(n\log n=o(n^2)\).

This does not mean \(A\) is always faster on every small input. Constants, memory behavior, and implementation overhead can matter in practice. Asymptotic complexity describes the long-term growth pattern.

Reading Comprehension Questions

  1. Why can a loop that runs 42 times be \(\Theta(1)\) rather than \(\Theta(n)\)?
  2. What code behavior often leads to logarithmic time?
  3. Why does a typical all-pairs comparison lead to quadratic time?
  4. If algorithm \(A\) has complexity \(\Theta(n^2)\) and algorithm \(B\) has complexity \(\Theta(n\log n)\), which usually scales better?
  5. Why are exponential algorithms usually not considered efficient?
  1. Answer: Because 42 is a constant independent of the input size. The amount of work is bounded by a fixed number.
  2. Answer: Repeatedly discarding a constant fraction of the remaining input, such as halving the search range.
  3. Answer: There are about \(n^2\) ordered pairs, or \(n(n-1)/2=\Theta(n^2)\) unordered distinct pairs.
  4. Answer: \(B\) usually scales better because \(n\log n\) grows slower than \(n^2\).
  5. Answer: Their running times grow so quickly that even moderate input sizes can become infeasible.

In-Class Activities

  1. Classify code: Label short code fragments as constant, logarithmic, linear, quadratic, or exponential.
  2. Doubling experiment: For \(n=10,20,40,80\), compare \(n\), \(n\log n\), \(n^2\), and \(2^n\). Describe what changes when \(n\) doubles.
  3. Algorithm match: Match binary search, sequential search, merge sort, selection sort, and subset generation to their typical complexity classes.

Homework Problems
