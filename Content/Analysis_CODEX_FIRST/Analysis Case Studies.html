Analysis Case Studies

Overview

The best way to learn algorithm analysis is to analyze real code shapes. This page collects the longer examples from the LaTeX chapter: sequential and nested loops, sorting algorithms, data-structure-dependent method calls, algebraic improvements, and binary search.

Loop Shapes

Consecutive loops are added. Nested loops are multiplied only after you understand how many times the inner loop runs for each outer-loop value.

Consecutive Loops 
int q = 0;
for (int i = 1; i <= n; i++) {
    q = q + i * i;
}
for (int j = 1; j <= n; j++) {
    q = q * j;
}

Each loop runs \(n\) times, but one happens after the other. The total is \(n+n=2n=\Theta(n)\).

Nested Loops 
double v = 0;
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= n; j++) {
        v = v + a[i] * a[j];
    }
}

The inner assignment runs \(n\) times for each of \(n\) outer iterations. The total is \(n\cdot n=\Theta(n^2)\).

Quick check: What is the worst-case complexity of this code? 

for (int i = 0; i < n; i++) {
    for (int j = 0; j < 50; j++) {
        a[i][j] = b[i][j] * x;
    }
}

The inner loop runs 50 times, a constant. The outer loop runs \(n\) times, so the total running time is \(\Theta(n)\), not \(\Theta(n^2)\).

If an inner loop limit depends on an outer-loop variable, a summation is often the clearest analysis. For example, if the inner loop runs \(i\) times while \(i\) moves from 1 to \(n-1\), the total is \[ \sum_{i=1}^{n-1} i = \frac{(n-1)n}{2}=\Theta(n^2). \]

Sorting Examples

Simple sorting algorithms are useful analysis examples because the inner-loop bounds often change during the algorithm.

Bubble Sort 
void bubbleSort(int[] a) {
    for (int i = a.length - 1; i > 0; i--) {
        for (int j = 0; j < i; j++) {
            if (a[j] > a[j + 1]) {
                swap(a, j, j + 1);
            }
        }
    }
}

The inner loop runs \(n-1\), then \(n-2\), then \(n-3\), and so on down to 1. Therefore the number of comparisons is \[ (n-1)+(n-2)+\cdots+1=\frac{(n-1)n}{2}=\Theta(n^2). \] Even if the array is already sorted and the swap never happens, the comparisons still follow this quadratic pattern in this version.

Insertion Sort 
void insertionSort(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int v = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > v) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = v;
    }
}

In the worst case, the while loop moves through almost all of the sorted prefix on each iteration, giving \[ \sum_{i=1}^{n-1} i=\Theta(n^2). \] In the best case, the array is already sorted, the while condition fails quickly, and the algorithm runs in \(\Theta(n)\) time.

Data Structure Costs

The same high-level algorithm can have different complexity depending on the data structure. Insertion sort over an array-backed list has constant-time get and set, so it behaves like the array version. If the same code is used on a linked list where get(i) and set(i,x) require traversal, those calls are no longer constant.

In the linked-list version, each inner-loop iteration may cost \(\Theta(j)\) rather than \(\Theta(1)\). Summing those costs can push the overall worst-case running time from \(\Theta(n^2)\) to \(\Theta(n^3)\). The important lesson is not that linked lists are bad; it is that an algorithm must fit the operations its data structure supports well.

Operation family Typical array-backed cost Typical linked cost
Indexed get(i) or set(i,x) \(\Theta(1)\) \(\Theta(i)\), or \(\Theta(n)\) in a coarse worst-case bound
Stack push/pop at the active end \(\Theta(1)\) amortized or worst case depending on implementation \(\Theta(1)\)
Hash table search/insert/delete Not the usual representation Average \(\Theta(1)\), worst case \(\Theta(n)\)
Balanced search tree search/insert/delete Not the usual representation \(\Theta(\log n)\)

Helper Calls

A loop containing a method call must include the cost of that method call. In Java, a method such as retainAll repeatedly asks whether another collection contains an element. The cost depends on the other collection. 

for (int r = 0; r < size; r++) {
    if (c.contains(elementData[r])) {
        elementData[w++] = elementData[r];
    }
}

If the current ArrayList has \(n\) elements and c has \(m\) elements, then:

  • If c is an ArrayList or LinkedList, contains is \(\Theta(m)\), so the loop is \(\Theta(nm)\).
  • If c is a TreeSet, contains is \(\Theta(\log m)\), so the loop is \(\Theta(n\log m)\).
  • If c is a HashSet, contains is average-case \(\Theta(1)\), so the loop is average-case \(\Theta(n)\).

The outer loop did not change. The helper operation changed.

Algebraic Improvements

Sometimes a better algorithm comes from recognizing a mathematical formula instead of looping through the definition.

Summing from \(m\) to \(n\) 
int sumFromMToN(int m, int n) {
    int sum = 0;
    for (int i = m; i <= n; i++) {
        sum += i;
    }
    return sum;
}

This direct version takes \(\Theta(n-m+1)\) time. Using the formula \[ \sum_{k=m}^{n} k = \frac{n(n+1)}{2}-\frac{(m-1)m}{2} \] gives a constant-time version: 

int sumFromMToN(int m, int n) {
    return n * (n + 1) / 2 - (m - 1) * m / 2;
}
Avoiding Repeated Powers

If power(a, i) takes \(\Theta(i)\) time, then computing \(a^0+a^1+\cdots+a^{n-1}\) by calling power(a, i) inside a loop costs \[ \sum_{i=0}^{n-1} i=\Theta(n^2). \] A loop that carries the previous power forward computes the same sum in \(\Theta(n)\) time.

Binary Search

Binary search works on a sorted array. It compares the target with the middle element and discards half of the remaining search interval. 

int binarySearch(int[] a, int val) {
    int left = 0;
    int right = a.length - 1;
    while (right - left >= 0) {
        int middle = (left + right) / 2;
        if (val == a[middle]) {
            return middle;
        } else if (val < a[middle]) {
            right = middle - 1;
        } else {
            left = middle + 1;
        }
    }
    return -1;
}

The body of the loop does constant work. The worst case occurs when the target is not found and the search interval is halved until it becomes empty. After \(k\) iterations, the active interval has size about \(n/2^k\). The loop stops when this reaches 1 or less, so \(2^k\) is about \(n\), which means \(k=\Theta(\log n)\).

Therefore iterative binary search has worst-case complexity \(\Theta(\log n)\). The best case is \(\Theta(1)\), when the target is already at the middle.

Summary

  • Analyze loops from the inside out.
  • Add consecutive work; multiply nested work only after checking actual loop counts.
  • Use summations when inner-loop bounds change.
  • Include helper-method and data-structure operation costs.
  • Look for mathematical identities that avoid unnecessary loops.
  • For binary search, repeated halving leads to logarithmic time.

Reading Comprehension Questions

  1. Why do consecutive loops that each run \(n\) times give \(\Theta(n)\), while nested loops can give \(\Theta(n^2)\)?
  2. Why does bubble sort's comparison count involve the sum \(1+2+\cdots+(n-1)\)?
  3. Why can insertion sort have different best-case and worst-case complexities?
  4. Why does using a linked list with indexed get and set calls change the analysis?
  5. Why is binary search logarithmic?
  1. Answer: Consecutive loops are added: \(n+n=2n\). Nested loops run the inner loop for each outer iteration, so if both loops run \(n\) times the total is \(n\cdot n\).
  2. Answer: The inner loop runs \(n-1\) times on the first pass, then \(n-2\), and so on down to 1.
  3. Answer: In an already sorted array, the while loop stops immediately each time. In reverse order, each new value moves through the whole sorted prefix.
  4. Answer: Indexed access in a linked list requires traversal, so calls that were constant time in an array-backed list may become linear in the index.
  5. Answer: Each iteration discards about half of the remaining interval. The number of halvings needed to reduce \(n\) items to one item is \(\Theta(\log n)\).

In-Class Activities

  1. Loop audit: For several nested loops, write the exact summation before simplifying to a \(\Theta\)-bound.
  2. Sorting traces: Trace bubble sort and insertion sort on a sorted array and on a reverse-sorted array. Count comparisons or shifts.
  3. Data structure swap: Take a loop that calls contains. Analyze it when the collection is an ArrayList, TreeSet, and HashSet.
  4. Binary search intervals: Starting with \(n=64\), write the active interval size after each unsuccessful binary-search iteration.

Homework Problems

  1. Analyze selection sort. Give best-case and worst-case complexities and justify the bound.
  2. Analyze standard \(n\) by \(n\) matrix multiplication and explain why it is \(\Theta(n^3)\).
  3. Suppose power(a, i) takes \(\Theta(i)\). Analyze a loop that calls it for every \(i\) from 0 to \(n-1\).
  4. For retainAll, analyze the cost when the tested collection has \(m\) items and is implemented as a linked list, balanced tree, and hash table.
  5. Prove that binary search makes at most \(\lfloor \log_2 n\rfloor+1\) loop iterations in the worst case.
