Introduction: Algorithms, Data Structures, and Problems

Overview

Computer science is not only about writing programs. It is also about choosing useful ways to organize information, designing precise methods for solving problems, and understanding how those choices affect the amount of time and memory required.

This textbook studies three closely related ideas:

  • Problems: tasks we want a computer to solve, such as searching for an item, sorting a list, finding a shortest path, or maintaining a priority queue.
  • Algorithms: step-by-step methods for solving problems.
  • Data structures: ways of organizing data so that important operations can be performed effectively.

These ideas are inseparable in practice. An algorithm often depends on how the data is organized, and a data structure is useful because of the operations it supports. The same problem can often be solved in many ways using different combinations of algorithms and data structures. Some combinations are simple, some are efficient, and some are both. One goal of this textbook is to help you compare these choices and understand the tradeoffs among simplicity, efficiency, memory use, and flexibility.

Problems, Algorithms, and Data Structures

It is useful to separate several ideas that are often mixed together when we first learn to program.

Idea Question it answers Examples
Problem What task must be solved? Given a collection and a target value, determine whether the target appears.
Algorithm What method solves the task? Linear search, binary search, or interpolation search.
Data structure How is the information organized? An unsorted array, sorted array, hash table, or search tree.

A problem describes the desired relationship between input and output. It does not say how to produce the output.

For example, the Sorting problem asks us to rearrange values into order, but it does not require a particular sorting method. Similarly, the Searching problem asks whether a target value appears in a collection, but it does not say whether we should scan the values one at a time, repeatedly divide a sorted list in half, or use some other approach.

An algorithm is a method for solving a problem. More formally, an algorithm is a precise, finite sequence of steps that transforms valid input into the required output for a problem. The same problem may have many algorithms, and the best choice may depend on the input size, the available memory, the data structure being used, and whether we care more about simplicity, worst-case guarantees, or practical speed.

For searching, linear search, binary search, and interpolation search are different algorithms for the same basic problem, but which one is best depends on how the data is organized. For sorting, there are many algorithms, including insertion sort, merge sort, quicksort, heapsort, tree sort, and radix sort, and each has different tradeoffs in terms of speed, memory use, and simplicity.

A data structure is a way of representing and organizing data together with the operations that the organization is designed to support.

For searching, the organization of the data often determines which algorithms are available. If the values are stored in an unsorted array, linear search is the natural choice because there is no ordering information to use. If the values are stored in a sorted array, binary search becomes possible because we can inspect a middle value and rule out half of the remaining positions. If the records are stored in a hash table, a key can be used to compute a likely location for the desired record.

Sorting algorithms also depend on data organization. Many sorting algorithms, such as insertion sort, merge sort, and quicksort, are commonly described for arrays. Heapsort uses an array organized as a heap, where parent-child relationships are represented by index positions. Tree sort uses a search tree, where values are inserted into a branching structure and then read back in sorted order. In each case, the algorithm is not just a list of steps; it is a list of steps applied to data organized in a particular way.

Once these three ideas are separated, several other concerns become easier to discuss. We want to be sure an algorithm is correct, meaning that it produces the required output for every valid input. We need to understand the assumptions an approach depends on, such as whether the data is sorted, whether keys can be compared, or whether extra memory is available. We need to analyze an approach to understand how much time and memory it uses as the input size grows. We need to implement algorithms and data structures as working code in particular programming languages. And we need to compare tradeoffs: one approach may be simpler, another faster, another more memory-efficient, and another easier to update or maintain.

In searching, correctness means that the algorithm reports a match exactly when the target value appears in the collection. Linear search is correct because it checks each possible location before deciding the target is absent. Binary search depends on the values being sorted, because each step uses the sorted order to discard half of the remaining positions. Interpolation search makes an even stronger assumption: it uses the values themselves to estimate where the target is likely to be, so its behavior depends on how evenly the values are distributed.

Analysis helps compare these searching algorithms. Linear search is simple and works on an unsorted array, but it may inspect every item, giving \(O(n)\) worst-case time, which means the work grows roughly linearly with the number of items. Binary search uses the sorted order to reduce the remaining search range by about half each step, giving \(O(\log n)\) worst-case time, which grows much more slowly than linear time. Hash table lookup can be faster still on average, often \(O(1)\), meaning roughly constant time per lookup, but it requires extra structure, uses additional memory, and does not keep the records in sorted order. These are examples of tradeoffs: to make searching faster, we may have to sort the data first, store extra information, give up sorted-order traversal, or use code that is harder to implement correctly.

Sorting gives another view of the same ideas. Correctness means that the output contains the same values as the input, but rearranged into sorted order. Different algorithms achieve this in different ways: insertion sort repeatedly places one more value into its proper position, merge sort divides the input and merges sorted pieces, quicksort partitions values around a pivot, heapsort organizes the array as a heap, and tree sort inserts values into a search tree before reading them back in order. In each case, we need to justify that the algorithm both preserves all of the input values and places them in the required order.

The algorithms also make different assumptions and involve different tradeoffs. Radix sort, for example, needs values with a structure such as digits or characters; heapsort needs the array to be treated as a heap; merge sort often uses extra temporary storage; and quicksort is usually fast in practice but can behave poorly with unlucky pivot choices.

Implementation details can affect both searching and sorting. A binary search implementation must compute middle positions carefully and update the search range correctly. A hash table implementation must choose a hash function and a method for handling collisions. A merge sort implementation may use temporary arrays, while a linked-list version can merge by changing references. A quicksort implementation must choose pivots and handle equal values carefully. These details do not change the high-level problem, but they can affect correctness, memory use, constant factors, and how easy the code is to understand.

The searching example is worth one more look because it shows how the same problem can lead to different algorithms, data structures, assumptions, and tradeoffs. The following table compares several approaches based on how the data is organized.

Data organization Search method Typical search cost What the organization buys Tradeoff
Unsorted list or array Sequential search \(O(n)\) No special organization is required. Search may need to inspect every record.
Sorted array Binary search \(O(\log n)\) The middle record can be used to discard half of the remaining records. Insertions and deletions may require shifting items to preserve sorted order.
Hash table Hash table lookup Expected \(O(1)\) The key is used to go directly to the likely location of the record. Records are not automatically kept in sorted order, and collisions must be handled.
Search tree Tree search Often \(O(\log n)\) Each comparison chooses which subtree to continue searching. The tree must be maintained, and unbalanced trees can perform poorly.

In every row, the problem is the same: determine whether a given value appears. What changes is the organization of the data and the algorithm that organization makes natural. An unsorted array invites sequential search. A sorted array makes binary search possible. A hash table supports lookup by key. A search tree supports ordered search.

This section introduced the main vocabulary used throughout the textbook. A problem describes the task, an algorithm gives a method for solving it, and a data structure organizes the information used by the method. Later sections will also consider correctness, assumptions, analysis, implementation, and tradeoffs.

Two Small Examples

The ideas above are easier to see in small examples. The first example uses a simple sequence of values. The second uses a data structure whose behavior is essential to the algorithm.

Finding the Largest Value

Suppose we want to find the largest value in a collection. The problem describes the task: given a nonempty collection of values, return a value that is at least as large as every other value in the collection. For instance, if the list contains \(3, 8, 2, 5, 1, 7\), the largest value is \(8\). The problem statement does not say how to find that value.

One simple algorithm scans through the collection from left to right. It keeps track of the largest value seen so far. When the algorithm sees a larger value, it updates the stored value. After all values have been examined, the stored value is returned.

This algorithm is usually described using an array or list as the data structure. The values are stored in a sequence, and the algorithm examines them one at a time. The method does not require the values to be sorted or organized in any special way.

In pseudocode, the algorithm looks like this: 

largest(A):
  best = A[0]
  for each remaining value x in A:
    if x > best:
      best = x
  return best

This example also previews some of the other concerns from the previous section. The algorithm is correct because, after each step, best stores the largest value seen so far. It uses one pass through the collection, so the amount of work grows linearly with the number of values. Its implementation is simple: a loop and one variable are enough.

Checking Balanced Parentheses

Now suppose we want to check whether the parentheses in a string are balanced. For example, (()()) is balanced, but (() and ())( are not. The problem is to determine whether every opening parenthesis is matched by a later closing parenthesis in the correct order.

A useful data structure for this problem is a stack. A stack stores items in last-in, first-out order, meaning that the most recently added item is the first one removed. Think of a stack of plates: the last plate added to the stack is the first one removed. The two main stack operations are push, which adds an item to the top of the stack, and pop, which removes and returns the item from the top. Some stack implementations also provide peek, which returns the top item without removing it, but this algorithm does not need that operation.

The stack organization matches the parentheses problem. The most recent unmatched opening parenthesis should be the first one matched by a closing parenthesis. The stack keeps track of exactly those opening parentheses that have been seen but not yet matched.

The algorithm scans the string from left to right. When it sees an opening parenthesis, it pushes it onto the stack. When it sees a closing parenthesis, it pops one opening parenthesis from the stack. If a closing parenthesis appears when the stack is empty, the string is not balanced. At the end, the string is balanced exactly when the stack is empty.

In pseudocode, the algorithm looks like this: 

balancedParentheses(S):
  create an empty stack
  for each character c in S:
    if c is '(':
      push(c)
    else if c is ')':
      if the stack is not empty:
        pop()
      else:
        return false
  if the stack is empty:
    return true
  else:
    return false

This example depends more strongly on the data structure than the first one did. The algorithm still makes only one pass through the input, but it uses extra memory to remember unmatched opening parentheses. That extra memory is a useful tradeoff because it makes the algorithm simple and systematic.

Data Structures Preview

The Data Structures section studies common ways to organize information. Each structure is designed around a different set of operations and tradeoffs. Some structures keep items in a sequence, some organize items by keys, some arrange values hierarchically, and some represent relationships among objects.

Some important data structures include:

  • Arrays and Dynamic Arrays: Store items in indexed positions. They support fast access by index, but insertions and deletions in the middle may require shifting items.
  • Linked Lists: Store items in nodes connected by references. They support efficient local insertion and deletion once the relevant position is known, but reaching a position may require traversal.
  • Stacks: Support last-in, first-out access. They are useful for undo histories, recursion, expression processing, and depth-first search.
  • Queues and Deques: Support processing in arrival order or adding and removing from both ends. They appear in scheduling, buffering, and breadth-first search.
  • Sets, Maps, and Hash Tables: Organize items by value or key. They are useful when the main task is lookup, insertion, deletion, or associating keys with values.
  • Trees and Heaps: Organize data hierarchically. Search trees, heaps, and expression trees use tree structure in different ways.
  • Graphs: Model relationships among objects. They are used for networks, maps, dependencies, schedules, and many other systems.
  • Disjoint Sets: Maintain a collection of non-overlapping groups and support efficient union and find operations.

The following small examples illustrate several common ways data can be organized.

Structure Example organization
Array

Items occupy numbered positions. Arrays support fast access by index, but inserting or deleting in the middle may require shifting items.

Typical use: indexed sequences and dynamic arrays.

Linked List

Items are stored in nodes connected by references. Linked lists support efficient local insertion and deletion once the position is known, but traversing the list may be needed to find that position.

Typical use: sequential structures with frequent local updates.

Tree

Trees organize data by parent-child relationships. They are useful for hierarchical structures and appear in search trees, heaps, expression trees, and file systems.

Typical use: hierarchical organization and structured search.

Graph

Graphs model pairwise relationships among objects. Vertices represent the objects, and edges represent connections among them.

Typical use: networks, maps, dependencies, and connectivity.

Disjoint Set

Disjoint sets partition items into non-overlapping groups. The main operations are finding which group an item belongs to and merging two groups.

Typical use: connectivity problems and Kruskal's algorithm.

Algorithm Techniques Preview

The Techniques section studies recurring strategies for designing algorithms. A technique is not one algorithm. It is a general pattern that can lead to many algorithms for different problems.

The table below gives a brief preview. The examples are included to make the categories concrete; the later technique and algorithm pages explain the methods in detail.

Technique Core idea Representative algorithms
Brute Force Directly try possible solutions or directly apply the problem statement. Brute force methods are often simple, useful as baselines, and sometimes good enough for small inputs. Sequential search, selection sort, exhaustive search for subset sum, naive string matching.
Decrease-and-Conquer Solve a smaller version of the problem, then extend or use that solution. The problem size may decrease by one, by a constant amount, by a constant factor, or by a variable amount. Binary search, insertion sort, topological sorting, Euclid's algorithm.
Divide-and-Conquer Split the problem into subproblems, solve the subproblems recursively, and combine their answers to solve the original problem. Merge sort, quicksort, binary tree traversals, closest pair of points, Strassen's algorithm.
Transform-and-Conquer Change the representation, organization, or form of the input so that the problem becomes easier to solve. Presorting, heap construction, Gaussian elimination, balanced search trees.
Space-Time Tradeoff Use extra memory to reduce running time, often by storing information that will be needed later. Hash tables, lookup tables, counting sort, memoization, Horspool's string matching.
Greedy Algorithms Build a solution by repeatedly making a locally best choice. A greedy algorithm is useful only when those local choices can be justified as leading to a global solution. Kruskal's algorithm, Prim's algorithm, Dijkstra's algorithm, Huffman coding, activity selection.
Dynamic Programming Break a problem into overlapping subproblems and store their answers so repeated work is avoided. Fibonacci with memoization, coin changing, edit distance, 0-1 knapsack, Floyd-Warshall.
Backtracking Explore choices systematically, abandoning partial solutions when they cannot lead to a valid complete solution. N-queens, subset sum search, graph coloring, Hamiltonian cycle search, maze solving.

Reading Comprehension Questions

  1. Problem versus algorithm: What is the difference between a problem and an algorithm?
  2. Data structures: Why can changing the data structure change which algorithms are natural or efficient?
  3. Searching assumptions: What assumption does binary search depend on that linear search does not?
  4. Search tradeoffs: Why might a hash table be useful for searching, and what is one tradeoff of using one?
  5. Correctness: For sorting, what two things must be true for the output to be correct?
  6. Largest value example: In the largest-value algorithm, what does the variable best represent as the algorithm runs?
  7. Stack operations: What do the stack operations push and pop do?
  8. Balanced parentheses: Why is a stack a natural data structure for checking balanced parentheses?
  9. Data structures preview: Give one example of a data structure that organizes items by position, one that organizes items hierarchically, and one that represents relationships among objects.
  10. Algorithm techniques: What is the difference between an algorithm and an algorithm design technique?
  1. Answer: A problem describes the task to be solved: the desired relationship between input and output. An algorithm gives a method for solving that task.
  2. Answer: A data structure determines how information is organized and which operations are easy or expensive. For example, a sorted array makes binary search possible, while an unsorted array naturally leads to sequential search.
  3. Answer: Binary search depends on the values being sorted. It uses the sorted order to discard about half of the remaining positions at each step. Linear search does not require the data to be sorted.
  4. Answer: A hash table can make lookup very fast on average because a key is used to compute a likely location for the desired record. One tradeoff is that hash tables use extra structure and memory, do not keep records automatically sorted, and must handle collisions.
  5. Answer: A correct sorting algorithm must preserve the input values and place them in the required order. In other words, the output should contain the same values as the input, rearranged into sorted order.
  6. Answer: The variable best stores the largest value seen so far. After each step, it should be at least as large as every value examined up to that point.
  7. Answer: push adds an item to the top of a stack. pop removes and returns the item from the top of the stack.
  8. Answer: A stack is natural because parentheses must be matched in last-in, first-out order. The most recent unmatched opening parenthesis should be the first one matched by a later closing parenthesis.
  9. Answer: An array organizes items by position. A tree organizes items hierarchically. A graph represents relationships among objects.
  10. Answer: An algorithm is a specific method for solving a problem. An algorithm design technique is a general strategy or pattern that can lead to many algorithms for different problems.
