Introduction: Algorithms, Data Structures, and Problems (DRAFT!)

Overview

Computer science is not only about writing programs. It is also about choosing useful ways to organize information, designing precise methods for solving problems, and understanding how those choices affect the amount of time and memory required.

This textbook studies three closely related ideas:

  • Problems: tasks we want a computer to solve, such as searching for an item, sorting a list, finding a shortest path, or maintaining a priority queue.
  • Algorithms: step-by-step methods for solving problems.
  • Data structures: ways of organizing data so that important operations can be performed effectively.

These ideas are inseparable in practice. An algorithm often depends on a data structure, and a data structure is useful only because it supports certain operations. Analysis gives us a language for comparing these choices.

Problems, Algorithms, Data Structures, and Implementations

It is useful to separate several ideas that are often mixed together when we first learn to program.

Idea Question it answers Example
Problem What task must be solved? Given a list of values, put them in sorted order.
Algorithm What method solves the task? Merge sort, quicksort, insertion sort, or selection sort.
Data structure How is the information organized? An array, linked list, heap, hash table, tree, or graph.
Implementation How is the idea written in a programming language? A Java method, C++ function, or Python function.
Analysis How much time or memory does it use? Linear search takes \(O(n)\) time; binary search takes \(O(\log n)\) time.

A problem describes the desired input-output behavior. It does not say how to produce the output. For example, the sorting problem asks us to rearrange values into order, but it does not require a particular sorting method.

An algorithm gives a method for solving a problem. The same problem may have many algorithms, and the best choice may depend on the input size, the available memory, the data structure being used, and whether we care more about simplicity, worst-case guarantees, or practical speed.

A data structure organizes information so that certain operations are convenient. For example, a stack is designed around adding and removing from one end, a queue is designed around processing items in arrival order, and a hash table is designed around fast lookup by key.

An implementation turns the idea into working code. Two implementations can represent the same data structure differently, and two programs can implement the same algorithm in different languages. Analysis helps us understand which differences matter.

A First Example: Searching

Suppose we have a collection of student records, and each record has a student ID. The problem is:

Searching Problem

Given a collection of records and a target ID, determine whether a record with that ID appears in the collection. If it does, return the matching record.

This problem can be approached in several ways. The best choice depends on how the data is organized and which operations need to be fast.

Organization Possible method Typical cost Tradeoff
Unsorted list or array Sequential search \(O(n)\) Simple and flexible, but may need to inspect every record.
Sorted array Binary search \(O(\log n)\) Fast search, but maintaining sorted order after updates may be costly.
Hash table keyed by ID Hash table lookup Expected \(O(1)\) Very fast lookup, but does not automatically keep records in sorted order.
Search tree keyed by ID Tree search Often \(O(\log n)\) Supports ordered traversal and ordered queries, but must maintain tree structure.

Notice that the problem did not change. In every case, we are still trying to find a record with a given ID. What changed was the organization of the data and the algorithmic method used to search it.

This is a recurring theme. A good solution is rarely just an algorithm or just a data structure. It is a combination of a problem, a representation, a method, and an analysis of the resulting costs.

Two Perspectives

This material can be used in more than one type of course. The same ideas appear from different directions.

Data Structures Perspective

In a data structures course, we often begin by asking what operations a collection should support. Should it allow fast access by position? Fast insertion at the front? Fast lookup by key? Ordered traversal? Efficient removal of the highest-priority item?

Once the desired operations are clear, we choose a representation and implement the operations. The central questions are:

  • What values are stored?
  • What operations are supported?
  • What invariant keeps the structure valid?
  • How expensive is each operation?
  • What tradeoffs does this representation make?

Algorithms Perspective

In an algorithms course, we often begin with a problem to solve. We then choose a method: scan the input, divide the problem into smaller parts, make a greedy choice, store partial answers, search through possibilities, or transform the representation.

The central questions are:

  • What problem is being solved?
  • What is the main idea of the algorithm?
  • Why does the algorithm produce a correct answer?
  • How much time and memory does it use?
  • Which data structures help the algorithm run efficiently?

These perspectives overlap. Data structures are implemented using algorithms, and many algorithms depend on data structures. Studying them together helps explain why some approaches are simple, some are efficient, and some are both.

Data Structures Preview

The Data Structures section studies common ways to organize information. Each structure is designed around a different set of operations and tradeoffs. This section will eventually include small SVG diagrams for each structure.

Placeholder for visual catalog

This section should become a grid of short cards. Each card should include a small SVG diagram, a brief description, typical operations, and a link to the corresponding page.

  • Arrays and Dynamic Arrays: Store items in indexed positions. They support fast access by index, but insertions and deletions in the middle may require shifting items.
  • Linked Lists: Store items in nodes connected by references. They support efficient local insertion and deletion once the relevant position is known, but finding a position may require traversal.
  • Stacks: Support last-in, first-out access. They are useful for undo histories, recursion, expression processing, and depth-first search.
  • Queues and Deques: Support processing in arrival order or adding and removing from both ends. They appear in scheduling, buffering, and breadth-first search.
  • Trees: Organize data hierarchically. Search trees, heaps, and expression trees use tree structure in different ways.
  • Hash Tables: Use hash functions to support fast lookup by key in many practical settings.
  • Graphs: Model relationships among objects. They are used for networks, maps, dependencies, schedules, and many other systems.
  • Disjoint Sets: Maintain a collection of non-overlapping groups and support efficient union and find operations.

Algorithm Techniques Preview

The Techniques section studies recurring strategies for designing algorithms. A technique is not one algorithm. It is a general pattern that can lead to many algorithms.

Placeholder for technique catalog

This section should become a compact catalog of technique cards. Each card should include a short summary, a typical use case, and links to representative algorithms.

  • Brute Force: Try all possibilities or directly apply the problem statement. Brute force methods are often simple and useful as baselines.
  • Decrease-and-Conquer: Solve a smaller version of the problem, then extend the solution. Binary search and insertion sort are common examples.
  • Divide-and-Conquer: Split the problem into subproblems, solve them recursively, and combine the results. Merge sort is a central example.
  • Transform-and-Conquer: Change the representation or problem form so that the solution becomes easier. Presorting and heap construction are examples.
  • Greedy Algorithms: Build a solution by repeatedly making a locally best choice. Some greedy methods are optimal, but they require careful justification.
  • Dynamic Programming: Store solutions to overlapping subproblems so they do not need to be recomputed.
  • Backtracking: Explore choices systematically and abandon partial solutions that cannot lead to a valid final answer.

Reading Comprehension Questions

  1. Problem versus algorithm: What is the difference between a problem and an algorithm?
  2. Data structures: Why can changing the data structure change the cost of solving the same problem?
  3. Searching example: What is one advantage and one disadvantage of storing student records in sorted order by ID?
  4. Two perspectives: How does a data structures course perspective differ from an algorithms course perspective?
  5. Analysis: Why is it not enough to know that an algorithm eventually produces the correct answer?
  1. Answer: A problem describes the task to be solved. An algorithm gives a method for solving that task.
  2. Answer: A data structure determines which operations are easy or expensive. The same search problem can have different costs depending on whether the records are stored in an unsorted list, sorted array, hash table, or tree.
  3. Answer: One advantage is that binary search becomes possible. One disadvantage is that insertions may require work to maintain sorted order.
  4. Answer: A data structures course often starts with operations and representations. An algorithms course often starts with problems and methods for solving them. The two perspectives overlap because algorithms use data structures and data structures are implemented with algorithms.
  5. Answer: Correctness matters, but we also need to know whether the algorithm uses a reasonable amount of time and memory as the input grows.

In-Class Activities

  1. Problem, Algorithm, Structure: For each task below, identify the problem, one possible algorithm, and one useful data structure: finding a contact by name, printing tasks in priority order, checking whether two cities are connected by roads.
  2. Search Tradeoffs: Compare an unsorted array, sorted array, hash table, and search tree for storing student records by ID. Discuss which is best if searches are common but insertions are rare.
  3. Course Perspective: In small groups, choose one topic such as binary search, stacks, or Dijkstra's algorithm. Describe how the topic might be introduced in a data structures course and how it might be introduced in an algorithms course.

Homework Problems

  1. Classify the Ideas: For each item, classify it as a problem, algorithm, data structure, implementation detail, or analysis statement: sorting, merge sort, array, Java method, \(O(n \log n)\), shortest path, priority queue, binary search.
  2. Choose an Organization: A library stores books and wants to support searching by ISBN, printing all books alphabetically by title, and adding new books regularly. Describe two possible organizations and the tradeoffs between them.
  3. Same Problem, Different Methods: Describe two different ways to solve the problem of finding whether a value appears in a collection. For each method, state what assumption it makes about how the collection is organized.
