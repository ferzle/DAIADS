Kruskal's Algorithm

Problem Solved

Kruskal's Algorithm solves the Minimum Spanning Tree problem.

Design and Strategy

Kruskal's Algorithm builds a minimum spanning tree by considering the edges of a connected, weighted, undirected graph from smallest weight to largest. Starting with no edges selected, it repeatedly chooses the lightest edge that does not create a cycle. The process stops when \(V-1\) edges have been selected, which is exactly the number of edges in a spanning tree on \(V\) vertices.

This is a greedy algorithm because each step makes the best choice available at that moment: select the lightest edge that can safely be added. Once an edge is selected, the algorithm never removes it. Even though these choices are made one at a time, the final result is guaranteed to be a minimum spanning tree.

To decide whether an edge is safe to add, consider its two endpoints. If there is a path between them using the already selected edges, then adding the new edge would create a cycle, so the edge must be skipped. Otherwise, the edge joins two separate connected components and can be selected.

Efficient implementations usually keep track of the connected components with a disjoint-set data structure, also called union-find. The details of that data structure are not needed to understand Kruskal's Algorithm here; conceptually, we only need to know whether two vertices are already connected.

High-Level Algorithm

  1. Sort all edges into nondecreasing order by weight.
  2. Start with no selected edges.
  3. Process the edges from smallest weight to largest.
    1. If the selected edges do not already contain a path between the endpoints, select the edge.
    2. Otherwise, skip the edge because adding it would create a cycle.
  4. Stop when \(V-1\) edges have been selected.

Note that negative edge weights do not cause a problem for Kruskal's Algorithm. Since the edges are processed from smallest weight to largest, negative-weight edges are simply considered before zero- and positive-weight edges.

Why the Greedy Choice Works

Suppose Kruskal is about to select an edge \(e\) that joins two currently separate components. Any spanning tree must eventually contain some edge that connects those two sides. Since Kruskal considers edges from smallest weight to largest, \(e\) is no heavier than any alternative edge that could be used instead at this point.

More formally, imagine a minimum spanning tree that contains all of Kruskal's earlier choices but does not contain \(e\). Adding \(e\) to that tree creates a cycle. That cycle contains another edge connecting the same two sides. Replacing that edge with \(e\) cannot increase the total weight, so there is still a minimum spanning tree containing all of Kruskal's choices. Repeating this argument shows that every greedy choice is safe.

Pseudocode

The pseudocode leaves the path test abstract. Conceptually, we need to determine whether the selected edges already contain a path between the endpoints of an edge. Efficient implementations normally use union-find to keep track of this information. 

Kruskal(vertices, edges)
  sort edges into nondecreasing order by weight
  selected = empty set

  for each edge (u, v) in edges
      if selected does not contain a path from u to v
          add (u, v) to selected
          if selected contains |vertices| - 1 edges
              return selected
  return selected

For a connected graph, the algorithm returns a minimum spanning tree. If the graph is disconnected, it has no spanning tree; the same process instead returns a minimum spanning forest.

Time/Space Analysis

Time Complexity: Sorting the \(E\) edges takes \(O(E \log E)\) time. After sorting, Kruskal's Algorithm examines each edge at most once. The remaining cost depends on how we determine whether the selected edges already contain a path between the two endpoints.

A simple but inefficient implementation could run a graph search through the selected edges each time an edge is considered. Since the selected edges always form a forest with at most \(V-1\) edges, one such search takes \(O(V)\) time in the worst case. Repeating this for as many as \(E\) edges gives \(O(EV)\) time for the path tests alone. The total time would then be \(O(E \log E + E V)=O(E V)\). But we can do better.

A union-find data structure avoids repeatedly searching the forest. It supports a find operation to determine which component contains a vertex and a union operation to merge two components. With a standard efficient implementation, these operations can be bounded by \(O(\log V)\) time each. Since Kruskal performs only a constant number of these operations per edge, all of the component tests take \(O(E \log V)\) time. Together with sorting, this gives \(O(E\log E + E \log V) = O(E \log V)\) time overall for a connected graph. If you are wondering why this simplifies to \(O(E \log V)\) instead of \(O(E \log E)\), note that \(E\) is at most \(V^2\) in a simple graph, so \(\log E = O(\log V)\). We will not justify the union-find bounds here; they depend on how the data structure is implemented.

A More Precise Bound: More advanced versions of union-find use techniques called path compression and union by rank or size to make these operations even faster: a sequence of operations takes \(O(\alpha(V))\) amortized time per operation, where \(\alpha\) is the inverse Ackermann function and grows extremely slowly. Thus the union-find work is \(O(E\alpha(V))\), and sorting still dominates. This stronger bound is stated here for completeness; its proof and the details of these union-find optimizations are beyond the scope of this page.

Space Complexity: Union-find uses \(O(V)\) extra space to represent the connected components, not counting the input edge list or the edges returned as output. If the input edge list is sorted in place, no additional \(O(E)\) storage is needed for the edge list. If a separate sorted copy is created, that copy requires \(O(E)\) additional space.

Variations/Improvements

Efficient implementations of Kruskal's Algorithm typically use a disjoint-set, or union-find, data structure to keep track of the connected components formed by the selected edges. More advanced versions of union-find use techniques called path compression and union by rank or size to make these operations even faster.

Equal-weight edges do not require a special rule and may be processed in any order. Different tie-breaking choices can produce different spanning trees, but Kruskal's Algorithm will still produce a minimum spanning tree. If all edge weights are distinct, the minimum spanning tree is unique. Equal weights make multiple MSTs possible, but do not guarantee that more than one exists.

Connections and Comparisons

A graph search such as breadth-first search or depth-first search can also produce a spanning tree of a connected graph. However, these algorithms do not use edge weights, so there is no reason for the resulting spanning tree to have minimum total weight. Kruskal's Algorithm uses the weights explicitly, always considering the lightest remaining edge first while avoiding cycles.

Kruskal's Algorithm is also a natural application of the union-find data structure. As edges are selected, union-find maintains the connected components formed by those edges. This makes it possible to determine efficiently whether the endpoints of a candidate edge are already joined by a selected path.

Kruskal's Algorithm and Prim's Algorithm both solve the minimum spanning tree problem greedily, but they organize their choices differently. Kruskal considers edges globally from smallest to largest, so its selected edges may form several separate trees that gradually merge. Prim begins at one vertex and maintains a single growing tree throughout the algorithm.

  8. Equal and Negative Weights: How does Kruskal's Algorithm handle equal-weight edges? Why do negative edge weights not require any change to the algorithm?
  9. Disconnected Graphs: What does Kruskal's Algorithm produce if the input graph is disconnected?
  1. Answer: It considers edges from smallest weight to largest and selects the next edge whose addition would not create a cycle.
  2. Answer: The existing path together with the new edge would form a cycle, so the edge cannot be part of the growing forest.
  3. Answer: A tree on \(V\) vertices has exactly \(V-1\) edges. Since Kruskal never creates a cycle, selecting \(V-1\) edges in a connected graph produces a spanning tree.
  4. Answer: The selected edges already contain the path \(A-B-C\). Adding \((A,C)\) would therefore create the cycle \(A-B-C-A\), so the edge must be skipped.
  5. Answer: Adding Kruskal's selected edge to that minimum spanning tree creates a cycle. An appropriate edge on that cycle can be removed and replaced by Kruskal's edge without increasing the total weight, producing another minimum spanning tree that contains Kruskal's choice.
