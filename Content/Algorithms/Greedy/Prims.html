Prim's Algorithm

Problem Solved

Prim's Algorithm solves the Minimum Spanning Tree problem.

Design and Strategy

Prim's Algorithm builds a minimum spanning tree of a connected, weighted, undirected graph by starting at one vertex and growing a single tree. At each step, it selects a minimum-weight edge with exactly one endpoint already in the tree. The other endpoint is then added to the tree. The process stops when every vertex is in the tree.

This is a greedy algorithm: once it chooses the cheapest edge that can expand the current tree, it never reverses that choice. Because each selected edge joins the current tree to a new vertex, the selected edges remain connected and never contain a cycle.

A useful way to organize the choices is to keep a key for each vertex outside the tree. The key of a vertex is the weight of the cheapest known edge connecting that vertex to the current tree. A min-priority queue stores candidate vertices by key, so the vertex with the smallest key can be selected efficiently. When a new vertex enters the tree, its incident edges may give some outside vertices cheaper ways to connect, so their keys are updated and new priority-queue entries are added.

At every stage, the selected edges form a tree containing exactly the vertices that have already been reached. For each vertex v outside that tree, key[v] is the weight of the lightest known edge from the tree to v. Therefore, the outside vertex with the smallest key is attached by a lightest edge leaving the current tree. This is how the priority-queue implementation carries out Prim's greedy choice.

The greedy choice is safe because of the cut property. A cut divides the vertices into two groups. At any point in Prim's Algorithm, consider the cut with the vertices already in the tree on one side and all remaining vertices on the other. Prim selects a lightest edge crossing this cut. If a minimum spanning tree does not contain that edge, adding it creates a cycle containing some other edge that also crosses the cut. That other edge cannot be lighter than Prim's choice, so replacing it with Prim's edge gives another minimum spanning tree that includes the greedy choice. Repeating this argument shows that every choice made by Prim can be part of a minimum spanning tree.

High-Level Algorithm

  1. Choose any start vertex s.
  2. Set key[s] = 0. Set the key of every other vertex to infinity, and place s in a min-priority queue.
  3. While the priority queue is not empty:
    1. Remove the vertex u with the smallest key.
    2. If u is already in the tree, skip this queue entry.
    3. Otherwise, add u to the tree.
    4. For each edge from u to a vertex v outside the tree, if that edge is lighter than key[v], update key[v], record u as the parent of v, and insert the new key for v into the priority queue.
  4. If the graph is connected, the parent edges form a minimum spanning tree.

Implementation in Java, C++, Python

These implementations represent the graph with an adjacency list and use a min-priority queue to decide which vertex to add to the tree next. Because the graph is undirected, each edge appears in the adjacency lists of both of its endpoints. The array key stores, for each vertex not yet in the tree, the weight of the cheapest known edge that could connect it to the tree. The array parent stores the other endpoint of that edge. Thus, when the algorithm finishes, the parent array describes the minimum spanning tree: for every vertex v except the start vertex, the edge (parent[v], v) belongs to the tree. The start vertex has parent -1.

The inTree array records which vertices have already been added to the growing tree. The priority queue stores candidate vertices ordered by their key values. Rather than modifying an existing queue entry when a cheaper way to attach a vertex is found, the implementation simply inserts a new entry with the smaller key. This means the queue may contain more than one entry for the same vertex. The newer, cheaper entry will be removed first because the priority queue always removes the minimum key. Any older entries for that vertex will be ignored if they are later removed from the queue, since the vertex is already in the tree.

The implementations below use vertex 0 as the start vertex. It is not too difficult to generalize this to allow any vertex to be chosen as the starting point.

import java.util.*;

class Edge {
  int to, weight;

  Edge(int to, int weight) {
    this.to = to;
    this.weight = weight;
  }
}

class Prim {
  static int[] primMST(List<Edge>[] graph) {
    int n = graph.length;
    boolean[] inTree = new boolean[n];
    int[] key = new int[n];
    int[] parent = new int[n];

    Arrays.fill(key, Integer.MAX_VALUE);
    Arrays.fill(parent, -1);
    key[0] = 0;

    PriorityQueue<int[]> pq =
        new PriorityQueue<>(Comparator.comparingInt(a -> a[0]));
    pq.add(new int[]{0, 0}); // {key, vertex}

    int verticesAdded = 0;

    while (!pq.isEmpty()) {
      int[] current = pq.poll();
      int u = current[1];

      if (inTree[u]) continue;

      inTree[u] = true;
      verticesAdded++;

      for (Edge e : graph[u]) {
        int v = e.to;
        if (!inTree[v] && e.weight < key[v]) {
          key[v] = e.weight;
          parent[v] = u;
          pq.add(new int[]{key[v], v});
        }
      }
    }

    if (verticesAdded != n) return null;
    return parent;
  }
}

struct Edge {

vector<int> primMST(const vector<vector<Edge>>& graph) {
  int n = graph.size();
  vector<bool> inTree(n, false);
  vector<int> key(n, INT_MAX);
  vector<int> parent(n, -1);

  // {key, vertex}; greater makes this a min-priority queue.
  priority_queue<pair<int, int>,
                 vector<pair<int, int>>,
                 greater<pair<int, int>>> pq;

  key[0] = 0;
  pq.push({0, 0});

  int verticesAdded = 0;

  while (!pq.empty()) {
    int u = pq.top().second;
    pq.pop();

    if (inTree[u]) continue;

    inTree[u] = true;
    verticesAdded++;

    for (const Edge& e : graph[u]) {
      int v = e.to;
      if (!inTree[v] && e.weight < key[v]) {
        key[v] = e.weight;
        parent[v] = u;
        pq.push({key[v], v});
      }
    }
  }

  if (verticesAdded != n) return {};
  return parent;
}
import heapq


def prim_mst(graph):
    n = len(graph)
    in_tree = [False] * n
    key = [float("inf")] * n
    parent = [-1] * n

    key[0] = 0
    pq = [(0, 0)]  # (key, vertex)
    vertices_added = 0

    while pq:
        _, u = heapq.heappop(pq)

        if in_tree[u]:
            continue

        in_tree[u] = True
        vertices_added += 1

        for v, weight in graph[u]:
            if not in_tree[v] and weight < key[v]:
                key[v] = weight
                parent[v] = u
                heapq.heappush(pq, (key[v], v))

    if vertices_added != n:
        return None
    return parent

If the graph is disconnected, not all vertices can be reached from the start vertex, so these implementations return no spanning tree.

Time/Space Analysis

Time Complexity: A simple "work per iteration times number of iterations" analysis can overestimate the running time here. When a vertex \(u\) is added to the tree, examining its adjacency list takes \(O(\deg(u))\) time, which can be as large as \(O(V)\). Multiplying this worst case by \(V\) vertices would give \(O(V^2)\) just for examining edges. However, not every vertex has \(V\) incident edges. Across all vertices, the total number of adjacency-list entries is \(2E\), since each undirected edge appears once at each endpoint. Thus all of the adjacency-list scans together take only \(O(E)\) time.

Whenever examining an edge produces a smaller key for a vertex, a new entry is inserted into the min-priority queue. There can be at most \(O(E)\) such insertions. The lazy implementation may also remove stale entries from the queue, but there can be at most \(O(E)\) removals because every removed entry was previously inserted. Since the heap can contain \(O(E)\) entries, each insertion or removal takes \(O(\log E)\) time. Thus the priority-queue work takes \(O(E\log E)\) time overall.

For a simple graph, \(E=O(V^2)\), so \(\log E=O(\log V^2)=O(\log V)\). Therefore the running time can also be written as \(O(E\log V)\).

A simpler implementation can avoid the priority queue and scan all vertices to find the smallest key at each step. With an adjacency matrix, this version runs in \(O(V^2)\) time. It can be attractive for dense graphs, while the \(O(E\log V)\) priority-queue version is generally preferable for sparse graphs.

Space Complexity: The key, parent, and inTree arrays use \(O(V)\) extra space. Because the lazy priority queue may contain multiple entries for the same vertex, it can use \(O(E)\) extra space in the worst case. Thus the total extra space is \(O(V+E)\), not counting the adjacency-list representation of the input graph. A priority queue that supports an efficient decrease-key operation can keep only one queue entry per vertex, reducing the extra heap space to \(O(V)\).

Variations/Improvements

Prim's Algorithm can be implemented in several ways depending on how the graph is represented. The adjacency-list and min-priority-queue version above runs in \(O(E \log V)\) time and is usually preferable for sparse graphs. A simpler adjacency-matrix version that scans all vertices to find the next minimum key runs in \(O(V^2)\) time and can be competitive on dense graphs.

More sophisticated priority queues can improve the theoretical running time further. For example, a Fibonacci heap supports the key decreases that occur while processing edges in \(O(1)\) amortized time and removal of the minimum in \(O(\log V)\) amortized time. This gives Prim's Algorithm a running time of \(O(E + V\log V)\). Fibonacci heaps are considerably more complicated than the priority queues used here, so we mention this bound only as an example of how the choice of data structure can affect an algorithm's running time.

The start vertex does not affect the minimum possible total weight, but it can affect which MST is produced when several MSTs exist. Equal-weight choices can also be broken in different ways. If all edge weights are distinct, the MST is unique, so every run of Prim's Algorithm produces the same tree regardless of the start vertex.

Prim's Algorithm works correctly with negative edge weights. Negative weights cause no difficulty because the algorithm only compares edge weights and repeatedly chooses the lightest edge that connects the current tree to a new vertex.

If the graph is disconnected, no spanning tree exists. The implementation above detects this and reports failure. A variation can instead restart Prim's Algorithm from an unvisited vertex whenever the priority queue becomes empty; doing so produces a minimum spanning forest, with one minimum spanning tree for each connected component.

Connections and Comparisons

Prim's Algorithm and Kruskal's Algorithm both solve the minimum spanning tree problem using a greedy strategy, but they organize their choices differently. Prim always maintains one growing tree and repeatedly adds the lightest edge that connects that tree to a new vertex. Kruskal considers edges globally from smallest to largest and may maintain several separate trees that gradually merge.

Prim is also closely related to Dijkstra's shortest-path algorithm, which we will encounter later. Both algorithms can use an adjacency list and a min-priority queue, repeatedly remove the vertex with the smallest current priority, and examine its incident edges. The important difference is what that priority represents. In Prim, key[v] is the weight of the cheapest known edge that can attach v to the growing tree. In Dijkstra, dist[v] is the length of the cheapest known path from the start vertex to v.

In Prim, the essential test and update are 

if !inTree[v] and e.weight < key[v]
  key[v] = e.weight
  parent[v] = u
  add (key[v], v) to the priority queue

Dijkstra uses almost the same code, but the corresponding test and update use the length of the path through u: 

if !inTree[v] and dist[u] + e.weight < dist[v]
  dist[v] = dist[u] + e.weight
  parent[v] = u
  add (dist[v], v) to the priority queue

Thus, the two algorithms can have nearly identical control structures even though they solve different problems. Prim chooses vertices according to the weight of a single edge connecting them to the tree, while Dijkstra chooses vertices according to the total length of a path from the start vertex.
