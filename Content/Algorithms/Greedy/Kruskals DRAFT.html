Kruskal's Algorithm

Problem Solved

Kruskal's Algorithm solves the Minimum Spanning Tree problem.

Design and Strategy

Kruskal's Algorithm builds a minimum spanning tree of a connected, weighted, undirected graph by considering edges from smallest weight to largest. It adds an edge whenever doing so does not create a cycle. Since a spanning tree on \(V\) vertices has exactly \(V-1\) edges, the algorithm stops after selecting that many edges.

This is a greedy algorithm: at each step it makes the locally best available choice by taking the lightest edge that can safely be added, and it never reverses an earlier choice. The surprising fact is that these local choices always produce a minimum spanning tree.

Another way to view the cycle test is to ask whether the endpoints of an edge are already connected by the edges selected so far. If they are, adding the new edge would close a cycle, so the edge is skipped. Efficient implementations usually keep track of these connected components with a disjoint-set structure, also called union-find. The details of that data structure are not needed to understand the algorithm here.

A useful way to see why the greedy choice is safe is with an exchange argument. Suppose the edges selected so far are contained in some minimum spanning tree, and Kruskal next selects edge \(e\). If that tree does not contain \(e\), adding \(e\) creates a cycle. That cycle contains another edge leaving one of the components that \(e\) joins. This other edge cannot be lighter than \(e\), or Kruskal would already have considered and selected it. Replacing that edge with \(e\) therefore produces another minimum spanning tree that contains all of Kruskal's choices so far.

High-Level Algorithm

  1. Sort all edges into nondecreasing order by weight.
  2. Start with no selected edges.
  3. Process the edges from smallest weight to largest.
    1. If adding the edge would not create a cycle, select it.
    2. If adding the edge would create a cycle, skip it.
  4. Stop when \(V-1\) edges have been selected.

Pseudocode

The pseudocode leaves the cycle test abstract. In a small graph it can be checked directly; efficient implementations normally use union-find to perform this test quickly. 

Kruskal(vertices, edges)
  sort edges into nondecreasing order by weight
  selected = empty set

  for each edge e in edges
    if adding e to selected would not create a cycle
      add e to selected

      if selected contains |vertices| - 1 edges
        return selected

  return selected

For a connected graph, the algorithm returns a minimum spanning tree. If the graph is disconnected, it cannot contain a spanning tree; the same process instead returns a minimum spanning forest.

Time/Space Analysis

Time Complexity: Sorting the \(E\) edges takes \(O(E \log E)\) time. The algorithm then examines each edge at most once. The cost of deciding whether an edge creates a cycle depends on how that test is implemented. With the standard efficient approach using union-find, the cycle tests are fast enough that sorting dominates, giving an overall running time of \(O(E \log E)\).

Space Complexity: An efficient implementation uses \(O(V)\) extra space to keep track of connected components, not counting the input edge list or the edges returned as the output. If a separate sorted copy of the edge list is created rather than sorting the input in place, that copy requires an additional \(O(E)\) space.

Variations/Improvements

The main implementation issue in Kruskal's Algorithm is testing whether an edge would create a cycle. Repeatedly searching the selected edges from scratch would be inefficient. A disjoint-set, or union-find, data structure keeps track of which vertices are already connected and supports this test efficiently. More advanced implementations typically combine union by rank or size with path compression.

Equal-weight edges do not require a special rule. They may be processed in any order. Different orders can produce different spanning trees, but Kruskal's Algorithm still produces a minimum spanning tree. If all edge weights are distinct, the minimum spanning tree is unique. Equal weights can allow multiple MSTs, although they do not guarantee that multiple MSTs exist.

Connections and Comparisons

Kruskal's Algorithm and Prim's Algorithm both solve the minimum spanning tree problem greedily, but they organize their choices differently. Kruskal's Algorithm considers edges globally from smallest to largest. During the process, the selected edges may form several separate trees that gradually merge. Prim's Algorithm instead begins at one vertex and grows a single tree by repeatedly adding a light edge that connects the current tree to a new vertex.

Kruskal's Algorithm is especially natural when a graph is represented as an edge list, since its first step is to sort the edges. Prim's Algorithm is often a natural fit when the graph is represented by adjacency lists and a priority queue is available. The two algorithms can make different choices and produce different minimum spanning trees when several MSTs exist, but both always produce an MST on a connected weighted undirected graph.

In-Class Activities

  1. Trace the Algorithm: For the graph with edges \((A,B,4), (A,C,2), (B,C,1), (B,D,5), (C,D,3)\), sort the edges and process them in order. For each edge, record whether it is selected or skipped and give the final MST weight.
  2. Identify the Cycle: Suppose the currently selected edges are \((A,B), (B,C), (C,D)\). For each candidate edge \((A,C), (A,D), (D,E)\), decide whether Kruskal's Algorithm would accept it. For every rejected edge, identify the cycle it would create.
  3. Track Components: Start with vertices \(A,B,C,D,E,F\) and process the accepted edges \((A,C), (D,E), (B,C), (E,F), (C,D)\). After each edge, write the connected components formed by the selected edges. Use the component information to explain why an edge whose endpoints are in the same component must be rejected.
  4. Equal-Weight Choices: Consider edges \((A,B,1), (A,C,1), (B,C,1), (B,D,2), (C,D,2)\). Run Kruskal's Algorithm twice using two different orders for equal-weight edges. Compare the resulting spanning trees and their total weights.
  5. Find the First Rejection: For edges \((A,B,1), (B,C,2), (A,C,3), (C,D,4), (B,D,5)\), determine the first edge Kruskal's Algorithm rejects. Explain why all earlier edges are accepted and why this edge is not.
  6. Change One Weight: Return to the graph from the first activity, but change the weight of \((A,B)\) from 4 to 0. Run Kruskal's Algorithm again. Identify which edges are now selected or skipped differently and compare the new MST weight with the original one.
  7. Use the Demo: In the interactive demo, advance until the first edge is rejected. Before revealing the decision, identify a path already connecting the endpoints of that edge. Continue until the MST is complete and verify that exactly \(V-1\) edges were selected.
