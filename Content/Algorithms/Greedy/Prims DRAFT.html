Prim's Algorithm

Problem Solved

Prim's Algorithm solves the Minimum Spanning Tree problem.

Design and Strategy

Prim's Algorithm builds a minimum spanning tree of a connected, weighted, undirected graph by starting at one vertex and growing a single tree. At each step, it selects a minimum-weight edge with exactly one endpoint already in the tree. The other endpoint is then added to the tree. The process stops when every vertex is in the tree.

This is a greedy algorithm: once it chooses the cheapest edge that can expand the current tree, it never reverses that choice. Because the selected edge always joins the current tree to a new vertex, the selected edges remain connected and never contain a cycle.

A useful way to organize the choices is to keep a key for each vertex outside the tree. The key of a vertex is the weight of the cheapest known edge connecting that vertex to the current tree. A min-priority queue stores candidate vertices by key, so the vertex with the smallest key can be selected efficiently. When a new vertex enters the tree, its incident edges may give some outside vertices cheaper ways to connect, so their keys are updated and new priority-queue entries are added.

The greedy choice is safe because of an exchange argument. Let the vertices already reached by Prim form one side of a cut, with all remaining vertices on the other side. Prim selects a lightest edge crossing that cut. If a minimum spanning tree does not contain that edge, adding it creates a cycle containing some other edge that also crosses the cut. That other edge cannot be lighter than Prim's choice, so replacing it with Prim's edge gives another minimum spanning tree that includes the greedy choice.

High-Level Algorithm

  1. Choose any start vertex s.
  2. Set key[s] = 0. Set the key of every other vertex to infinity, and place s in a min-priority queue.
  3. While the priority queue is not empty:
    1. Remove the vertex u with the smallest key.
    2. If u is already in the tree, skip this queue entry.
    3. Otherwise, add u to the tree.
    4. For each edge from u to a vertex v outside the tree, if that edge is lighter than key[v], update key[v], record u as the parent of v, and insert the new key for v into the priority queue.
  4. The parent edges form a minimum spanning tree.

Implementation in Java, C++, Python

These implementations use an adjacency list and a min-priority queue. The priority queue stores candidate vertices ordered by their current key values. When a cheaper way to attach a vertex is found, a new entry is inserted into the queue. Older entries are simply ignored if that vertex has already been added to the tree. 

import java.util.*;

class Edge {
  int to, weight;

  Edge(int to, int weight) {
    this.to = to;
    this.weight = weight;
  }
}

class Prim {
  static int[] primMST(List<Edge>[] graph) {
    int n = graph.length;
    boolean[] inTree = new boolean[n];
    int[] key = new int[n];
    int[] parent = new int[n];

    Arrays.fill(key, Integer.MAX_VALUE);
    Arrays.fill(parent, -1);
    key[0] = 0;

    PriorityQueue<int[]> pq =
        new PriorityQueue<>(Comparator.comparingInt(a -> a[0]));
    pq.add(new int[]{0, 0}); // {key, vertex}

    int verticesAdded = 0;

    while (!pq.isEmpty()) {
      int[] current = pq.poll();
      int u = current[1];

      if (inTree[u]) continue;

      inTree[u] = true;
      verticesAdded++;

      for (Edge e : graph[u]) {
        int v = e.to;
        if (!inTree[v] && e.weight < key[v]) {
          key[v] = e.weight;
          parent[v] = u;
          pq.add(new int[]{key[v], v});
        }
      }
    }

    if (verticesAdded != n) return null;
    return parent;
  }
}

struct Edge {
  int to;
  int weight;
};

vector<int> primMST(const vector<vector<Edge>>& graph) {
  int n = graph.size();
  vector<bool> inTree(n, false);
  vector<int> key(n, INT_MAX);
  vector<int> parent(n, -1);

  // {key, vertex}; greater makes this a min-priority queue.
  priority_queue<pair<int, int>,
                 vector<pair<int, int>>,
                 greater<pair<int, int>>> pq;

  key[0] = 0;
  pq.push({0, 0});

  int verticesAdded = 0;

  while (!pq.empty()) {
    int u = pq.top().second;
    pq.pop();

    if (inTree[u]) continue;

    inTree[u] = true;
    verticesAdded++;

    for (const Edge& e : graph[u]) {
      int v = e.to;
      if (!inTree[v] && e.weight < key[v]) {
        key[v] = e.weight;
        parent[v] = u;
        pq.push({key[v], v});
      }
    }
  }

  if (verticesAdded != n) return {};
  return parent;
}
import heapq


def prim_mst(graph):
    n = len(graph)
    in_tree = [False] * n
    key = [float("inf")] * n
    parent = [-1] * n

    key[0] = 0
    pq = [(0, 0)]  # (key, vertex)
    vertices_added = 0

    while pq:
        _, u = heapq.heappop(pq)

        if in_tree[u]:
            continue

        in_tree[u] = True
        vertices_added += 1

        for v, weight in graph[u]:
            if not in_tree[v] and weight < key[v]:
                key[v] = weight
                parent[v] = u
                heapq.heappush(pq, (key[v], v))

    if vertices_added != n:
        return None
    return parent

For every vertex except the start vertex, parent[v] gives the other endpoint of the MST edge that connects v to the tree. For example, if parent[3] = 1, then edge (1,3) is in the resulting tree. These versions use the common "lazy" priority-queue approach: when a key decreases, they insert a new queue entry instead of searching for and changing the old one. If the graph is disconnected, they return no spanning tree.

Time/Space Analysis

Time Complexity: Each vertex is added to the tree at most once, and each edge is examined when one of its endpoints is added. Whenever an edge gives a vertex a smaller key, a new entry is inserted into the min-priority queue. Across the whole algorithm there are at most \(O(E)\) such updates. Each priority-queue insertion or removal costs logarithmic time. In the lazy implementation above the heap can contain \(O(E)\) entries, so the bound is \(O(E \log E)\), which is \(O(E \log V)\) for a simple graph.

A simpler implementation can avoid the priority queue and scan all vertices to find the smallest key at each step. With an adjacency matrix, that version runs in \(O(V^2)\) time. It can be attractive for dense graphs, but the priority-queue version is usually better for sparse graphs.

Space Complexity: The key, parent, and in-tree arrays use \(O(V)\) extra space. The lazy priority-queue implementation above can contain multiple entries for the same vertex, so the heap may use \(O(E)\) extra space in the worst case. Thus the extra space is \(O(V+E)\), not counting the adjacency-list representation of the input graph. A priority queue with an efficient decrease-key operation can reduce the extra heap space to \(O(V)\).

Variations/Improvements

Prim's Algorithm can be implemented in several ways depending on how the graph is represented. The adjacency-list and min-priority-queue version above runs in \(O(E \log V)\) time and is usually preferable for sparse graphs. A simpler adjacency-matrix version that scans all vertices to find the next minimum key runs in \(O(V^2)\) time and can be competitive on dense graphs.

The start vertex does not affect the minimum possible total weight, but it can affect which MST is produced when several MSTs exist. Equal-weight choices can also be broken in different ways. If all edge weights are distinct, the MST is unique, so every run of Prim's Algorithm produces the same tree regardless of the start vertex.

Unlike Dijkstra's shortest-path algorithm, Prim's Algorithm does not require nonnegative edge weights. Negative edge weights cause no difficulty: Prim still chooses the lightest edge that connects the current tree to a new vertex.

Connections and Comparisons

Prim's Algorithm and Kruskal's Algorithm both solve the minimum spanning tree problem greedily, but they organize their choices differently. Prim always maintains one connected tree and repeatedly chooses the lightest edge leaving that tree. Kruskal considers edges globally from smallest to largest and may maintain several separate trees that gradually merge.

Prim is also closely related to Dijkstra's shortest-path algorithm. Both repeatedly choose an unprocessed vertex with the smallest current key and then inspect its incident edges. The central difference is what the key means. In Prim, key[v] is the weight of the cheapest single edge that can attach v to the current tree. In Dijkstra, dist[v] is the length of the cheapest known path from the start vertex to v.

In the priority-queue-based code above, the essential update changes from 

if e.weight < key[v]
  key[v] = e.weight

in Prim to 

if dist[u] + e.weight < dist[v]
  dist[v] = dist[u] + e.weight

in Dijkstra. The control structure is nearly the same, but those two lines change the goal from finding a minimum spanning tree to finding shortest paths from one source.

  2. Track Keys: Use the same graph, starting at \(A\). After adding each vertex, record the current key and parent of every vertex still outside the tree. Identify which keys change and why.
  3. Change the Start: Run Prim's Algorithm on the same graph starting at \(D\) instead of \(A\). Compare the order of selected edges and verify that the final MST weight is unchanged.
  4. Tied Choices: Consider edges \((A,B,1), (A,C,1), (B,C,1), (B,D,2), (C,D,2)\). Starting at \(A\), make two different valid choices when equal-weight edges are available. Compare the resulting spanning trees and their total weights.
  5. Identify Crossing Edges: Suppose the current tree contains vertices \(\{A,C,D\}\) in a graph on \(\{A,B,C,D,E\}\). Given edges \((A,B,5), (A,C,2), (B,C,3), (C,D,1), (C,E,4), (D,E,6)\), list exactly the edges that leave the current tree and determine which one Prim would choose next.
