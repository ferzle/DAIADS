Binary Heaps

Overview and Structure

A binary heap is a tree-shaped data structure that keeps one extreme entry—either the minimum or the maximum—easy to access. It does not completely sort its entries. Instead, it imposes just enough structure to place the highest-priority entry at the root while supporting efficient insertion and removal.

It is helpful to distinguish the data structure from the interface it implements. A priority queue is an abstract data type that supports operations such as inserting an entry, inspecting the highest-priority entry, and removing it. A binary heap is one concrete way to implement that interface.

This page develops max-heaps, where larger keys have higher priority. In a min-heap, smaller keys have higher priority, and the same algorithms work with the comparisons reversed. For the priority-queue interface and simpler implementation choices, review the Priority Queues page.

Two properties define the structure of a binary heap:

  1. Complete-tree shape: The heap is a complete binary tree. Every level is full except possibly the last, and entries on the last level occupy the leftmost available positions. Consequently, a nonempty heap containing \(n\) entries has height \(\lfloor \log_2 n \rfloor\).
  2. Heap order: In a max-heap, the key stored at each node is greater than or equal to the keys stored at its children. In a min-heap, each parent's key is less than or equal to its children's keys.

Heap order does not sort the entire tree. For example, 72 appears to the left of the larger value 85, and values in different branches have no required relationship. The local parent-child rule guarantees only that the largest value, 90, is at the root. A heap is therefore not a binary search tree.

Array Representation

Although a binary heap is described as a tree, it is usually stored in an array. Because the tree is complete, its nodes have no gaps when listed level by level from left to right. They can therefore occupy consecutive array positions without storing child or parent references.

The root is stored first, followed by the nodes on each successive level from left to right. With zero-based indexing, the relatives of the node at index \(i\) are determined directly from its index:

  • left child: \(2i+1\),
  • right child: \(2i+2\), and
  • parent, when \(i>0\): \(\lfloor(i-1)/2\rfloor\).

The max-heap from the previous example is stored as [90, 72, 85, 31, 60, 40, 10, 20, 25, 55]. For example, the entry 85 is at index 2. Its children are at indices 5 and 6, and its parent is at index 0.

This implementation stores a fixed-capacity backing array and a logical size. Only indices 0 through size - 1 belong to the heap; later cells are unused capacity. Tests for whether a child exists must therefore compare its index with size, not with the physical length of the backing array.

Core Operations

The public operations largely match the priority-queue interface. This page assumes that the heap uses a fixed-capacity array. An insertion into a full heap fails and leaves the heap unchanged. The table uses max-heap names to make the selected extreme explicit; a more general implementation could instead use names such as peekBest and extractBest.

Operation Behavior Worst-Case Time
isEmpty() Report whether the heap is empty. \(\Theta(1)\)
isFull() Report whether the heap has reached its capacity. \(\Theta(1)\)
size() Return the number of stored entries. \(\Theta(1)\)
peekMax() Return the maximum entry without removing it. \(\Theta(1)\)
insert(entry) Insert a new entry. Return false if the heap is full; otherwise, return true. \(\Theta(\log n)\)
extractMax() Remove and return the maximum entry. \(\Theta(\log n)\)

Two private helpers restore heap order. siftUp moves a newly inserted entry toward the root, while siftDown moves a replacement entry toward the leaves. These helpers are implementation mechanisms rather than operations exposed through the priority-queue interface.

A resizable heap would grow its backing array when it becomes full rather than rejecting an insertion. Copying entries into a larger array makes an occasional insertion take \(\Theta(n)\) time, although insertion remains \(O(\log n)\) amortized when the capacity is doubled.

How the Operations Work

Heap updates handle shape and order separately. An entry is first added or removed in the position required by the complete-tree shape. If this disrupts heap order, one entry is moved along a single path until the order is restored.

peekMax

In a nonempty max-heap, the maximum entry is always at the root, which is stored at index 0. Thus, peekMax can return the maximum without searching the heap. The implementation must also define what happens when the heap is empty, such as signaling an error or returning a designated empty result.

insert

If the fixed-capacity array is full, insert returns false and leaves the heap unchanged. Otherwise, it places the new entry at index size, the next position required by the complete-tree shape, and increases size.

The existing entries still satisfy max-heap order, so the only possible violation is between the new entry and its parent. The siftUp helper repeatedly swaps the entry with its parent while the entry is larger. It stops when the entry reaches the root or is no larger than its parent. Once heap order has been restored, insert returns true.

Because siftUp is used here only to complete an insertion, we treat it as part of insert rather than as a separate operation. In contrast, siftDown is useful in several heap algorithms and is discussed separately.

siftDown

The siftDown helper repairs the subtree rooted at a given position when the entry at that position may be smaller than one or both of its children. It assumes that the subtrees rooted at those children are already valid heaps.

At each step, the entry is compared with its existing children. If either child is larger, the entry swaps with the larger child and continues from its new position. When two children are present, swapping with the smaller one could leave a violation with the larger one. The process stops at a leaf or when the entry is at least as large as every child.

Thus, siftDown repairs one path through an otherwise valid heap; it does not repair arbitrary disorder throughout a subtree. We will use this helper after replacing the root during extractMax.

extractMax

The maximum entry is at the root, but removing it directly would leave a gap at the beginning of the array. Instead, extractMax saves the root for return, moves the final entry to the root, decreases size, and calls siftDown at the root. If the heap is empty, extractMax signals the same empty-heap result used by peekMax.

Implementation

The following pseudocode describes a max-heap stored in a fixed-capacity array. A min-heap uses the same structure and algorithms with the priority comparison reversed.

Index and Comparison Helpers

parent(i):
    return floor((i - 1) / 2)

leftChild(i):
    return 2 * i + 1

rightChild(i):
    return 2 * i + 2

higherPriority(first, second):
    return first.key > second.key

Basic Queries

isEmpty(H):
    return H.size == 0

isFull(H):
    return H.size == length(H.A)

size(H):
    return H.size

peekMax(H):
    if H.size == 0:
        signal EMPTY_HEAP

    return H.A[0]

insert

insert(H, entry):
    if isFull(H):
        return false
    H.A[H.size] = entry
    H.size = H.size + 1
    siftUp(H, H.size - 1)

    return true

siftUp

siftUp(H, i):
    while i > 0:
        p = parent(i)
        if not higherPriority(H.A[i], H.A[p]):
            return

        swap(H.A[i], H.A[p])
        i = p

siftDown

siftDown(H, i):
    while leftChild(i) < H.size:
        left = leftChild(i)
        right = rightChild(i)
        bestChild = left

        if right < H.size and higherPriority(H.A[right], H.A[left]):
            bestChild = right

        if not higherPriority(H.A[bestChild], H.A[i]):
            return

        swap(H.A[i], H.A[bestChild])
        i = bestChild

extractMax

extractMax(H):
    if isEmpty(H):
        signal EMPTY_HEAP

    maximum = H.A[0]
    lastIndex = H.size - 1
    H.A[0] = H.A[lastIndex]
    H.A[lastIndex] = EMPTY
    H.size = H.size - 1

    if H.size > 0:
        siftDown(H, 0)

    return maximum

A resizable implementation would replace the failed full-heap insertion with an array-growth step. That occasional resize would take \(\Theta(n)\) time, while insertion would remain \(O(\log n)\) amortized if the capacity were doubled.

Time/Space Analysis

A complete binary tree with \(n\) entries has height \(\lfloor \log_2 n \rfloor\). Both siftUp and siftDown follow at most one path through the tree, so each takes \(O(\log n)\) time.

A successful insertion takes \(\Theta(1)\) time when the new entry already belongs below its parent and \(\Theta(\log n)\) time in the worst case when it moves to the root. An insertion into a full fixed-capacity heap returns false in \(\Theta(1)\) time. Similarly, extractMax takes \(\Theta(1)\) time when the replacement root requires no swaps and \(\Theta(\log n)\) time in the worst case.

The operations isEmpty, isFull, size, and peekMax inspect stored fields or the root, so each takes \(\Theta(1)\) time.

If the fixed backing array has capacity \(C\), the heap uses \(\Theta(C)\) storage, of which the first \(n\) positions are currently occupied. The iterative operations use only \(\Theta(1)\) auxiliary space. Recursive versions of siftUp or siftDown would use \(O(\log n)\) call-stack space.

A resizable implementation would occasionally require \(\Theta(n)\) time to copy the entries into a larger array. If the capacity is doubled when full, insertion remains \(O(\log n)\) amortized, and the array uses \(\Theta(n)\) space.

Searching for an arbitrary entry still takes \(O(n)\) time in the worst case. Heap order identifies the maximum, but it does not provide a search direction for other entries. Applications that need fast access to particular entries may maintain a separate map from identifiers to heap indices.

Applications

Because binary heaps efficiently implement priority queues, they can be used for the scheduling, graph-processing, event-simulation, and compression applications discussed on the Priority Queues page. Two uses of binary heaps that are especially worth emphasizing are:

  • Heapsort: arrange the entries into a heap and repeatedly move the root to its final position, producing an in-place \(O(n \log n)\) sorting algorithm.
  • Top-\(k\) selection: maintain a heap containing only the best \(k\) entries seen so far, using \(O(k)\) space rather than storing and sorting the entire input.

Comparisons and Tradeoffs

The Priority Queues page compares the operation costs of several simple implementations. A binary heap provides a useful balance: it supports both insertion and removal of the highest-priority entry in \(O(\log n)\) time while keeping the highest-priority entry available in \(\Theta(1)\) time.

  • Compared with sorted and unsorted arrays: a sorted array provides constant-time access to the best entry but requires linear-time insertion, while an unsorted array inserts in constant time but requires a linear search for the best entry. A binary heap avoids either operation being linear.
  • Compared with a balanced search tree: a binary heap is simpler and more compact when only an extreme entry is needed. Its array representation often gives it smaller constant factors and better memory locality than a pointer-based balanced search tree. A balanced search tree, however, additionally supports efficient search for arbitrary keys, predecessor and successor queries, and ordered traversal.
  • Compared with a pointer-based tree: the array representation avoids parent and child references and usually provides better memory locality. Its main limitation is that a fixed-capacity heap can become full; a resizable heap must occasionally allocate and copy a larger array.

Variations and Extensions

  • Min-heaps: reverse the priority comparison so that the smallest entry is stored at the root.
  • Resizable heaps: replace the fixed-capacity array with a dynamically resized array. An insertion that encounters a full array grows the capacity rather than failing.
  • d-ary heaps: allow each node to have up to \(d\) children. This reduces the height of the heap but requires examining more children during siftDown.
  • Indexed heaps: maintain a map from entry identifiers to array indices. This makes it possible to locate entries quickly for priority changes or removal, but the map must be updated after every swap.

Other heap data structures, including binomial, Fibonacci, and pairing heaps, use different representations and provide different tradeoffs. They are particularly useful when efficient merging or priority changes are important.

Common Pitfalls

  • Assuming total order: heap order constrains parent-child pairs but does not sort siblings or entries in different branches.
  • Mixing index conventions: zero-based and one-based heaps use different formulas for parents and children.
  • Confusing size and capacity: only indices below size contain heap entries; the remaining array positions are unused capacity.
  • Ignoring a full heap: insertion into a fixed-capacity heap must fail without changing the existing entries.
  • Choosing the wrong child: siftDown must examine every existing child and swap with the higher-priority one.
  • Repairing in the wrong direction: insertion may violate order with a parent and repairs upward, while replacing the root may violate order with a child and repairs downward.
  • Forgetting empty-heap behavior: peekMax and extractMax must use a clearly defined and consistent policy when the heap is empty.

Summary

A binary heap is a complete binary tree that is usually stored in level order in an array. Completeness allows parent and child positions to be computed directly from array indices, while heap order guarantees that the highest-priority entry is at the root without fully sorting the remaining entries.

In a max-heap, insertion places a new entry in the next available position and uses siftUp to restore order. Extraction replaces the root with the final entry and uses siftDown. Root inspection and basic size queries take \(\Theta(1)\) time, while successful insertion and extraction take \(\Theta(\log n)\) time in the worst case and \(\Theta(1)\) auxiliary space when implemented iteratively. A min-heap uses the same representation and algorithms with the priority comparisons reversed.
