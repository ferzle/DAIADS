Sets, Maps, and Hash Tables

Overview

Many algorithms need to store information so that particular items can be found efficiently. The information used to identify or locate an item is called its key. For example, a username might identify a user account, a student ID might identify a student record, and a word might identify an entry in a word-frequency table.

A set stores a collection of distinct keys and supports operations such as determining whether a particular key is present. A map, also called a dictionary, associates each key with a value. For example, a set might store the words that occur in a document, while a map might associate each word with the number of times it occurs.

Sets and maps describe the information being stored and the operations that may be performed, but they do not specify how the information is represented. They can be implemented using several data structures, including arrays, linked structures, search trees, and hash tables. The choice of implementation affects the efficiency of the operations and which additional operations can be supported efficiently.

A hash table is one important way to implement a set or a map. It uses a hash function to determine where each key should be stored. Hash tables are especially useful for operations involving exact keys, such as determining whether a username is already in use or retrieving the record associated with a student ID. When operations depend on the ordering of the keys, such as finding the smallest key or reporting all keys in a given range, an ordered implementation such as a balanced search tree may be more appropriate.

We begin by introducing sets and maps and considering some simple ways to implement them. We then explore hash tables in detail. When two or more keys are assigned to the same location in a hash table, a collision occurs. We conclude by examining two common approaches to handling collisions: separate chaining and open addressing.

More generally, the appropriate structure depends on the questions the application must answer. If we need to know only whether a key is present, a set stores all of the required information. If we need to associate some additional information with each key, we need a map.

The first question requires only membership information, so a set is sufficient. The other questions require a value associated with each word, so they require maps. In the second row, that value is a frequency; in the third, it is a position. Thus, a map contains a set of distinct keys together with one value associated with each key. Different keys may be associated with the same value, and the meaning and type of the values depend on the application.

These descriptions concern the logical information stored by the structures, not how that information is represented in memory. Either the set or the map in this example could be implemented using an array, a search tree, or a hash table. We consider how the choice of implementation affects the supported operations and their efficiency in the next section.

Choosing an Implementation

Once we have decided whether an application needs a set or a map, we must choose how to implement it. Different implementations can store the same logical information and support the same basic operations, but their efficiencies and additional capabilities may differ. The best choice therefore depends on the operations the application must perform.

For a set, the basic exact-key operations determine whether a key is present, insert a key, and remove a key. For a map, they retrieve the value associated with a key, insert or update a key-value pair, and remove a key-value pair. Some applications also require operations involving the ordering of the keys, such as finding the smallest key, visiting the keys in sorted order, or reporting all keys in a given range.

The same underlying data structures can usually be used to implement both sets and maps. A set implementation stores one key in each entry. A map implementation instead stores a key-value pair in each entry, but it uses the key to search for, arrange, or hash that pair. Once the matching key is found, the map can retrieve or modify its associated value. Thus, the main structural difference is that a map entry must store a value along with its key.

This difference also affects the behavior of insertion and updating. If a key is already present in a set, inserting it again leaves the set unchanged. A map contains only one entry for each key, so associating an existing key with a new value changes the value in that entry rather than adding a second entry with the same key. Consequently, set and map implementations often share most of their searching and storage logic, but their entries and some of their operations differ.

In an unordered array or linked list, inserting a new item can take constant time once its position is known. However, a set must first determine that the key is not already present, and a map must determine whether to add a new pair or update an existing one. That search can require examining all \(n\) keys, so the complete insertion or update operation takes \(O(n)\) time in the worst case.

Keeping an array sorted allows binary search to find an exact key in \(O(\log n)\) time and makes ordered traversal straightforward. Inserting or removing an item may require shifting many elements, however, so these operations take \(O(n)\) time in the worst case. A balanced search tree avoids this problem: it supports searching, insertion, and removal in \(O(\log n)\) worst-case time while also maintaining the keys in order.

A hash table provides a different tradeoff. It does not maintain the keys in a useful order, but its expected constant-time performance makes it an excellent choice when an application primarily searches for, inserts, or removes exact keys. For example, a hash table is well suited to checking whether a username is already in use or retrieving the record associated with a particular student ID. A balanced search tree is generally more appropriate if the application must frequently find the smallest key, traverse the keys in order, or perform range queries.

Thus, there is no single best implementation of a set or map. Simple sequence-based implementations may be sufficient for small collections, balanced search trees are useful when ordering matters, and hash tables are particularly effective for exact-key operations.
