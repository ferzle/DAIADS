Representing Linear Structures

Overview

A linear structure stores items in a sequence. Each item has a position relative to the others: before, after, first, last, next, and previous. Arrays and linked structures are two fundamental ways to represent such sequences. They support many of the same abstract ideas, but they make different tradeoffs in memory layout, access time, and update cost.

This page reviews arrays and introduces node-and-link representations. Later pages use these ideas to build lists, stacks, queues, priority queues, and other data structures.

Arrays

Basics

Here we provide a very brief review of arrays since we expect you have already encountered them in your previous programming course(s). We focus on the basic syntax, the underlying indexing idea, and the strengths and weaknesses that make arrays useful in some situations but less convenient in others.

An array stores items in a sequence of indexed positions. If an array has length \(n\), its valid indices are \(0,1,\ldots,n-1\). The three languages we focus on use mostly the same syntax for the most common array operations. In Java, C++, and Python, we use square brackets to access and update entries: a[2] gets the entry at index 2, and a[2] = 19 changes the entry at index 2 to 19.

In text, we typically use bracket notation to denote the values of an array. For instance, \(A = [12, 7, 19, 4, 15]\) is an array with five elements.

Array Syntax

Access and update syntax is nearly identical in Java, C++, and Python. Creation syntax and length syntax differ more.

Task Java C++ Python
Create with values int[] a={12,7,19,4,15}; int a[]={12,7,19,4,15}; a=[12,7,19,4,15]
Create with a constant length int[] a = new int[5]; int a[5]; a = [0] * 5
Create with variable length \(n\) int[] a = new int[n]; int* a = new int[n]; a = [0] * n

Get the length a.length store in variable (e.g. n) len(a)

A few important notes:

  • Built-in C++ arrays do not store their own size, so C++ programs often keep a separate variable such as n for the number of entries being stored.
  • In standard C++, the syntax int a[n]; is not valid when n is a runtime variable. For a runtime-sized array, we can allocate the array with new int[n], but then we are responsible for later freeing it with delete[] a. Since Java and Python handle memory management automatically, they do not have this issue.
  • Python's list is not exactly the same thing as a Java array or a built-in C++ array, but it is the usual Python structure used when we want simple array-like indexing. For now, the main point is the shared bracket notation: a[i] names the entry at index i.

Array Tradeoffs

  • Strength: Simple indexing. The expression a[i] refers to the entry at index i, and a[i] = value updates that entry.
  • Strength: Fast access and update. Reading or changing a[i] takes \(O(1)\) time.
  • Strength: Compact storage. Array entries are stored consecutively, so arrays have little extra storage overhead beyond the entries themselves.
  • Strength: Good memory locality. Because neighboring entries are stored near each other, arrays often work well with caches and are efficient to scan from left to right.
  • Weakness: Fixed index range. If an array has length \(n\), the valid indices are 0 through n - 1. Accessing an index outside this range is an error.
  • Weakness: Size management. Simple arrays have a fixed length after creation, so the programmer must choose a size ahead of time or create a new larger array and copy entries later. (But recall that the Python list is a resizable array, so it handles this issue automatically behind the scenes.)
  • Weakness: Costly insertions and deletions. Inserting or deleting near the beginning or middle usually requires shifting many entries to preserve order.
  • Weakness: Unused capacity or copying. If the array is larger than the number of items currently stored, some space is unused. If it is too small, the data must be copied into a larger array.

Dynamic Arrays

Many languages also provide a resizable or dynamic array structure. These structures preserve the basic idea of array indexing, but they can grow as items are added. Internally, a dynamic array usually stores items in an ordinary array; when that array runs out of capacity, the structure allocates a larger array and copies the existing entries. We will not focus on those details here, but these structures are worth recognizing because they are often what programmers use in practice.

  • Java: ArrayList<T> is the usual resizable array structure, where T is the element type. For example, an ArrayList<String> stores strings. To access an entry, use a.get(i) instead of a[i]. To update an entry, use a.set(i, value) instead of a[i] = value.
  • C++: vector<T> is the usual resizable array structure, where T is the element type. Unlike Java's ArrayList, a C++ vector still supports bracket notation: a[i] accesses an entry and a[i] = value updates an entry.
  • Python: list already behaves like a resizable array. It uses the same bracket notation as the simple examples above: a[i] accesses an entry and a[i] = value updates an entry.

Linked Representations

Overview

A second way to represent a linear structure is to store each item in a small object called a node. Each node stores a value and one or more links to other nodes. For a singly linked structure, each node stores a link to the next node in the sequence. For a doubly linked structure, each node stores links to both the next and previous nodes. For now, we focus on singly linked structures, but the same ideas apply to doubly linked structures and other variations.

Unlike an array, the nodes do not need to be stored next to each other in memory. The order is determined by the links, not by physical position. This makes some insertions and deletions efficient once the relevant node is known, but it means we lose direct indexed access.

Nodes

Overview

A node for a singly linked structure has two fields:

  • data: the item stored in the node. Sometimes we refer to this item as the node's value.
  • next: a reference, pointer, or link to the next node. If there is no next node, the next field stores a special value indicating that the reference does not point anywhere.

Conceptually, the next field tells us which node comes next in the sequence. In an implementation, this is represented as a pointer or reference to another node in memory. The actual reference value is not important for our purposes, so in diagrams we simply draw an arrow to the next node. If there is no next node, we label the link as null, although the language-specific name for this special value varies:

  • Java: uses null.
  • C++: uses nullptr in modern code.
  • Python: uses None.

Linked Lists

Overview

When we have a chain of nodes linked together, we often call the whole structure a linked list. The term "linked list" emphasizes the idea of a sequence of items connected by links. Each item is stored in a node, and the nodes are connected by their next fields.

Typically, the main reference to a linked list is a pointer to the first node, often called the "head" of the list, and the remaining nodes are accessed through following the links of each node.

Here is an example of a singly linked list with four nodes. The head reference points to the first node, which stores the value 14 and a link to the next node. The second node stores 8 and a link to the third node. The third node stores 31 and a link to the fourth node. The fourth node stores 5 and a null link, indicating the end of the list.

In the diagram, each node has two parts: a data field and a link to the next node. We also show the head reference and the null reference to indicate the start and end of the list.

If we want to represent a list in text, we can use an arrow notation to indicate the links between nodes. For instance, the list shown above could be represented as: head -> 14 -> 8 -> 31 -> 5 -> null.

Linked List Operations

Here is a partial list of some of the most basic operations that we will want to support for a linked list. Since linked lists are primarily used as a building block for other data structures, there is no official list of required operations, but these are some of the most common ones that we will want to support in later sections. The main purpose here is to give you an idea of how to work with nodes to create a linear structure.

insertAtHead(value):

To insert a new value at the head of the list, we need to create a new node, set the data field of the new node to the value being inserted, set its next link to the head (which points to the first node), and make the head reference point to the new node.

This operation works even when the list is empty; in that case, the new node's next field is set to null.

deleteAtHead():

This operation removes the first node from the list and returns the value from the data field of the removed node. To do so, we first save the value of the data field of the head node, then redirect the head reference to the next node (using head = head.next), effectively removing the old head from the list. Optionally, we can also reset the next link of the old head node to null, and free the memory used for the node in languages that require it.

This operation assumes that the list is nonempty. If head is null, there is no first node to remove.

insertAfter(node, value):

Given a reference to a node \(n\) in a list and a value \(v\), this operation inserts a new node containing the data field \(v\) after the given node \(n\), continuing the rest of the list after the new node. To do so, we first create a new node with the data set to \(v\), set the next link of the new node to n.next, then set n.next to the new node, effectively inserting the new node between \(n\) and its old successor.

This operation assumes that n is a reference to an existing node in the list. If n is null, there is no node after which to insert.

The order of these assignments matters. If we set n.next to the new node before saving the old value of n.next, we will lose access to the rest of the list.

deleteAfter(node):

This operation removes the node that comes after the given node \(n\) and returns the value from the data field of the removed node. To do so, we first save the value of the data field of the node after \(n\) (which is n.next.data), then redirect the next link of \(n\) to skip over the removed node and point to the following node (using n.next = n.next.next).

This operation assumes that n is a reference to an existing node and that n.next is not null. If n.next is null, there is no node after n to delete.

It may seem odd to have a method deleteAfter(n) instead of delete(n), but in a singly-linked list, we cannot delete a node if we only have a reference to that node. We would first need to find the node that comes before it in the list to redirect its next link to skip over the deleted node.

insertAtTail(value):

Many linked-list implementations also support inserting at the tail—that is, adding a new node at the end of the list. That operation is \(O(1)\) if the structure stores a tail reference (which we have not discussed yet), but \(O(n)\) if it must first traverse from the head to the last node. We will not go into the details of this operation here, but it is worth mentioning it as a common operation that is often supported by linked lists.

search(value):

This operation searches for a given value in the list and returns whether it is found or not, or alternatively, a reference to the node containing the value or null if the value is not found. To implement it, we can start at the head and follow next links until the value is found or the end is reached.

traverse():

Visit each node in order by repeatedly following next links. This is a vague operation that can be used for many purposes, such as printing the values of the nodes or performing some computation on the values.

Sometimes traversing requires walking two references through the list at the same time so we have access to the node of interest as well as its predecessor. This is particularly useful if you want to delete a node with a given property. Without a reference to the predecessor, we cannot redirect its next link to skip over the deleted node.

Linked List Implementation

Here are partial implementations of a linked list in Java, C++, and Python to give you an idea of how the code looks in different languages, and so you can see how working with linked lists compares to working with arrays. 

public class LinkedSequence {
    private static class Node {
        int data;
        Node next;

        Node(int data, Node next) {
            this.data = data;
            this.next = next;
        }
    }

    private Node head;

    public void insertAtHead(int value) {
        Node newNode = new Node(value, head);
        head = newNode;
    }

    public int deleteAtHead() {
        if (head == null) {
            throw new IllegalStateException("empty sequence");
        }
        int value = head.data;
        head = head.next;
        return value;
    }

    public void insertAfter(Node node, int value) {
        if (node == null) {
            throw new IllegalArgumentException("node is null");
        }
        Node newNode = new Node(value, node.next);
        node.next = newNode;
    }

    public int deleteAfter(Node node) {
        if (node == null || node.next == null) {
            throw new IllegalArgumentException("no node to delete");
        }
        int value = node.next.data;
        node.next = node.next.next;
        return value;
    }

    public Node search(int value) {
        Node current = head;
        while (current != null) {
            if (current.data == value) {
                return current;
            }
            current = current.next;
        }
        return null;
    }
}

        self.head = None

        new_node = Node(value, self.head)
        self.head = new_node

        if self.head is None:
            raise IndexError("empty sequence")
        value = self.head.data
        self.head = self.head.next
        return value

    def insert_after(self, node, value):
        if node is None:
            raise ValueError("node is None")

        node.next = new_node

        if node is None or node.next is None:
            raise ValueError("no node to delete")
        victim = node.next
        value = victim.data
        node.next = victim.next
        return value

        current = self.head
        while current is not None:
            if current.data == value:
                return current
            current = current.next
        return None

Linked List Variations

The singly linked structure above is only one linked representation. Later data structures may adjust the fields stored in each node or the references stored by the wrapper object to make certain operations faster or easier.

  • Doubly linked nodes: Each node stores both next and prev links, making it possible to move in either direction.
  • Tail reference: In addition to head, the structure may store a tail reference to the last node, which can make some end operations faster.
  • Circular links: The last node may link back to the first node instead of storing null.
  • Sentinel nodes: Some implementations use a special dummy node to simplify boundary cases such as inserting or deleting at the beginning.

Comparison and Analysis

Arrays and linked structures both represent linear data, but they organize that data in very different ways. An array stores entries in indexed positions, so it is good at jumping directly to a known index. A linked structure stores entries in nodes connected by links, so it is good at changing local connections once the relevant node is known.

The phrase once the relevant node is known is important. In a linked list, inserting or deleting after a node can be fast, but finding that node may require a traversal from the head. Therefore, the best representation depends not only on the operation, but also on what information the algorithm already has.

Here is a comparison of the two representations for various tasks and features. The time complexities are given in terms of \(n\), the number of entries in the structure, and the memory overhead is described in terms of how much extra information must be stored per entry.

Task or Feature Array Representation Linked Representation
Access by index Fast: \(O(1)\). The position of a[i] can be computed directly. Slow: \(O(i)\) (which is \(O(n)\) in the worst case). To reach index i, we usually start at head and follow i links.
Update by index Fast: \(O(1)\), assuming the index is valid. Usually \(O(i)\) (which is \(O(n)\) in the worst case), because we must first find the node at that position.
Insert at head Usually \(O(n)\), because existing entries must shift right to preserve order. \(O(1)\). Create a new node, point it to the old head, and update head.
Delete at head Usually \(O(n)\), because remaining entries must shift left to preserve order. \(O(1)\). Move head to the next node (or throw an exception if the list is empty).
Insert after a known location If the location is given by index \(i\), then usually \(O(n-i)\), which is \(O(n)\) in the worst case, because later entries must shift right. \(O(1)\), if we already have a reference to the node after which we are inserting.
Delete after a known node If the location is given by index \(i\), then usually \(O(n-i)\), which is \(O(n)\) in the worst case, because later entries must shift left. \(O(1)\), if we already have a reference to the previous node and that node has a successor.
Search by value Usually \(O(n)\) if the entries are unordered. Usually \(O(n)\), because we may need to follow links through every node.
Memory overhead Little extra per-entry overhead. A simple array mainly stores the entries themselves. Higher per entry. Each node stores data plus at least one link.
Memory locality Usually good. Neighboring entries are stored near each other, which can make scanning efficient. Often weaker. Nodes may be scattered in memory, so following links can be less cache-friendly.
Size flexibility Simple arrays have fixed capacity. Dynamic arrays can grow, but resizing requires copying entries. Flexible. Nodes can be allocated one at a time as the structure grows.

The main reason for these differences is that arrays make positions easy to compute, while linked structures make local rewiring easy. In an array, the location of a[i] can be computed directly from the start of the array and the index i. In a linked structure, there is no comparable formula for the node at position i; we must follow links to get there.

On the other hand, once we have the right node reference in a linked structure, inserting or deleting nearby nodes usually requires changing only a constant number of links. In an array, preserving order after an insertion or deletion usually requires shifting entries.

A useful rule of thumb is this: use an array representation when fast indexed access, compact storage, and good memory locality are important. Use a linked representation when the algorithm frequently changes local connections and already has references to the relevant nodes.

Common Pitfalls

  • Confusing indices with values: In an array, A[2] means the entry at index 2, not the value 2.
  • Forgetting that indices start at 0: An array of length \(n\) has valid indices 0 through n - 1.
  • Confusing length with capacity: An array-based structure may have extra unused space, especially when it is used to build a dynamic structure. So it is important to keep in mind that the number of entries in the array and the capacity of the array are not necessarily the same.
  • Confusing a node with its data: A node is the whole object containing data and next. The data value is only one field inside the node.
  • Losing part of a linked list: When inserting a node, save the old link before overwriting it. Otherwise, the rest of the list may become unreachable.
  • Ignoring null cases: Operations such as deleteAtHead and deleteAfter need to handle empty lists or missing successor nodes.
  • Overstating linked-list speed: Linked insertion or deletion is \(O(1)\) only when the relevant node reference is already known.

Summary and Key Takeaways

  • Linear structures store items in sequence. Arrays and linked structures are two common ways to represent that sequence.
  • Arrays use indices. The expression a[i] refers directly to the entry at index i, which makes access and update by index fast.
  • Arrays can require shifting. Inserting or deleting near the front or middle of an array usually requires moving later entries to preserve order.
  • Linked structures use nodes and links. Each node stores data and a reference to the next node, so the order is determined by links rather than by physical position in memory.
  • Linked structures support local rewiring. Once the relevant node is known, inserting or deleting nearby nodes can usually be done by changing a constant number of links.
  • Linked structures do not provide direct indexed access. To reach index i, we usually start at head and follow links one at a time.
  • The right representation depends on the operations. Arrays are often better for fast indexed access and compact storage. Linked structures are often better when local insertions and deletions are common and the relevant node references are already available.
