Representing Linear Structures

Overview

A linear structure stores items in a sequence. Each item has a position relative to the others: before, after, first, last, next, and previous. Arrays and linked structures are two fundamental ways to represent such sequences. They support many of the same abstract ideas, but they make different tradeoffs in memory layout, access time, and update cost.

This page reviews arrays and introduces node-and-link representations. Later pages use these ideas to build lists, stacks, queues, priority queues, and other data structures.

Arrays

Basics

Here we provide a very brief review of arrays since we expect you have already encountered them in your previous programming course(s). We focus on the basic syntax, the underlying indexing idea, and the strengths and weaknesses that make arrays useful in some situations but less convenient in others.

An array stores items in a sequence of indexed positions. If an array has length \(n\), its valid indices are \(0,1,\ldots,n-1\). The three languages we focus on use mostly the same syntax for the most common array operations. In Java, C++, and Python, we use square brackets to access and update entries: a[2] gets the entry at index 2, and a[2] = 19 changes the entry at index 2 to 19.

In text, we typically use bracket notation to denote the values of an array. For instance, \(A = [12, 7, 19, 4, 15]\) is an array with five elements.

Array Syntax

Access and update syntax is nearly identical in Java, C++, and Python. Creation syntax and length syntax differ more.

Task Java C++ Python
Create with values int[] a={12,7,19,4,15}; int a[]={12,7,19,4,15}; a=[12,7,19,4,15]
Create with a constant length int[] a = new int[5]; int a[5]; a = [0] * 5
Create with variable length \(n\) int[] a = new int[n]; int* a = new int[n]; a = [0] * n
Access entry at index 2 x = a[2]; x = a[2]; x = a[2]
Update entry at index 3 a[3] = 20; a[3] = 20; a[3] = 20
Get the length a.length store in variable (e.g. n) len(a)

A few important notes:

  • Built-in C++ arrays do not store their own size, so C++ programs often keep a separate variable such as n for the number of entries being stored.
  • In standard C++, the syntax "int a[n];" is not valid when n is a runtime variable. For a runtime-sized array, we can allocate the array with new int[n], but then we are responsible for later freeing it with delete[] a. Since Java and Python handle memory management automatically, they do not have this issue.
  • Python's list is not exactly the same thing as a Java array or a built-in C++ array, but it is the usual Python structure used when we want simple array-like indexing. For now, the main point is the shared bracket notation: a[i] names the entry at index i.

Array Tradeoffs

  • Strength: Simple indexing. The expression a[i] refers to the entry at index i, and a[i] = value updates that entry.
  • Strength: Fast access and update. Reading or changing a[i] takes \(O(1)\) time.
  • Strength: Compact storage. Array entries are stored consecutively, so arrays have little extra storage overhead beyond the entries themselves.
  • Strength: Good memory locality. Because neighboring entries are stored near each other, arrays often work well with caches and are efficient to scan from left to right.
  • Weakness: Fixed index range. If an array has length \(n\), the valid indices are 0 through n - 1. Accessing an index outside this range is an error.
  • Weakness: Size management. Simple arrays have a fixed length after creation, so the programmer must choose a size ahead of time or create a new larger array and copy entries later. (But recall that the Python list is a resizable array, so it handles this issue automatically behind the scenes.)
  • Weakness: Costly insertions and deletions. Inserting or deleting near the beginning or middle usually requires shifting many entries to preserve order.
  • Weakness: Unused capacity or copying. If the array is larger than the number of items currently stored, some space is unused. If it is too small, the data must be copied into a larger array.

Dynamic Arrays

Many languages also provide a resizable or dynamic array structure. These structures preserve the basic idea of array indexing, but they can grow as items are added. Internally, a dynamic array usually stores items in an ordinary array; when that array runs out of capacity, the structure allocates a larger array and copies the existing entries. We will not focus on those details here, but these structures are worth recognizing because they are often what programmers use in practice.

  • Java: ArrayList<T> is the usual resizable array structure, where T is the element type. For example, an ArrayList<String> stores strings. To access an entry, use a.get(i) instead of a[i]. To update an entry, use a.set(i, value) instead of a[i] = value.
  • C++: vector<T> is the usual resizable array structure, where T is the element type. Unlike Java's ArrayList, a C++ vector still supports bracket notation: a[i] accesses an entry and a[i] = value updates an entry.
  • Python: list already behaves like a resizable array. It uses the same bracket notation as the simple examples above: a[i] accesses an entry and a[i] = value updates an entry.

Linked Representations

Overview

A second way to represent a linear structure is to store each item in a small object called a node. Each node stores a value and one or more links to other nodes. For a singly linked structure, each node stores a link to the next node in the sequence. For a doubly linked structure, each node stores links to both the next and previous nodes. For now, we focus on singly linked structures, but the same ideas apply to doubly linked structures and other variations.

Unlike an array, the nodes do not need to be stored next to each other in memory. The order is determined by the links, not by physical position. This makes some insertions and deletions efficient once the relevant node is known, but it means we lose direct indexed access.

Nodes

Overview

A node for a singly linked structure has two fields:

  • data: the item stored in the node. Sometimes we refer to this item as the node's value.
  • next: a reference, pointer, or link to the next node. If there is no next node, the next field stores a special value indicating that the reference does not point anywhere.

Conceptually, the next field tells us which node comes next in the sequence. IN an implementation, this is represented as a pointer or reference toanother node in memory. The actual reference value is not important for our purposes, so in diagrams we simply draw an arrow to the next node. If there is no next node, we label the link as null, although the language-specific name for this special value varies:

  • Java: uses null.
  • C++: uses nullptr in modern code.
  • Python: uses None.

Linked Lists

Overview

When we have a chain of nodes linked together, we often call the whole structure a linked list. The term "linked list" emphasizes the idea of a sequence of items connected by links. Each item is stored in a node, and the nodes are connected by their next fields.

Typically, the main reference to a linked list is a pointer to the first node, often called the "head" of the list, and the remaining nodes are accessed through following the links of each node.

Linked List Operations

Here is a partial list of some of the most basic operations that we will want to support for a linked list. Since linked lists are primarily used as a builinding block for other data structures, there is no official list of required operations, but these are some of the most common ones that we will want to support in later sections. The main purpose here is to give you an idea of how to work with nodes to create a linear structure.

insertAtHead(value):

To insert a new value at the head of the list, we need to create a new node, set the data field of the new node to the value being inserted, set its next link to the head (which points to the first node), and make the head reference point to the new node.

deleteAtHead():

This operation removes the first node from the list and returns the value from the data field of the removed node. To do so, we first save the value of the data field of the head node, then redirect the head reference to the next node (using head = head.next), effectively removing the old head from the list. Optionally, we can also reset the next link of the old head node to null, and free the memory used for the node in languages that require it.

insertAfter(node, value):

Given a reference to a node \(n\) in a list and a value \(v\), this operation inserts a new node containing the data field \(v\) after the given node \(n\), continuing the rest of the list after the new node. To do so, we first create a new node with the data set to \(v\), set the next link of the new node to n.next, then set n.next to the new node, effectively inserting the new node between \(n\) and its old successor.

deleteAfter(node):

This operation removes the node that comes after the given node \(n\) and returns the value from the data field of the removed node. To do so, we first save the value of the data field of the node after \(n\) (which is n.next.data), then redirect the next link of \(n\) to skip over the removed node and point to the following node (using n.next = n.next.next).

It may seem odd to have a method deleteAfter(n) instead of delete(n), but in a singly-linked list, we cannot delete a node if we only have a reference to that node. We would first need to find the node that comes before it in the list to redirect its next link to skip over the deleted node.

search(value):

This operation searches for a given value in the list and returns whether it is found or not, or alternatively, a reference to the node containing the value or null if the value is not found. To implement it, we can start at the head and follow next links until the value is found or the end is reached.

traverse():

Visit each node in order by repeatedly following next links. This is a vague operation that can be used for many purposes, such as printing the values of the nodes or performing some computation on the values.

Sometimes traversing requires walking two references through the list at the same time so we have access to the node of interest as well as its predecessor. This is particularly useful if you want to delete a node with a given property. Without a reference to the predecessor, we cannot redirect its next link to skip over the deleted node.

Linked List Implementation

Here are partial implementations of a linked list in Java, C++, and Python to give you an idea of how the code looks in different languages, and so you can see how working with linked lists compares to working with arrays. 

public class LinkedSequence {
    private static class Node {
        int data;
        Node next;

        Node(int data, Node next) {
            this.data = data;
            this.next = next;
        }
    }

    private Node head;

    public void insertAtHead(int value) {
        Node newNode = new Node(value, head);
        head = newNode;
    }

    public int deleteAtHead() {
        if (head == null) {
            throw new IllegalStateException("empty sequence");
        }
        int value = head.data;
        head = head.next;
        return value;
    }

    public void insertAfter(Node node, int value) {
        if (node == null) {
            throw new IllegalArgumentException("node is null");
        }
        Node newNode = new Node(value, node.next);
        node.next = newNode;
    }

    public int deleteAfter(Node node) {
        if (node == null || node.next == null) {
            throw new IllegalArgumentException("no node to delete");
        }
        int value = node.next.data;
        node.next = node.next.next;
        return value;
    }

    public Node search(int value) {
        Node current = head;
        while (current != null) {
            if (current.data == value) {
                return current;
            }
            current = current.next;
        }
        return null;
    }
}

            current = current.next
        return None

Array vs. Linked Representation

Arrays and linked structures are both useful. The choice depends on which operations must be fast and what kind of memory layout is acceptable.

Feature Array Representation Linked Representation
Access item by index Fast: \(O(1)\) Slow: usually \(O(n)\)
Insert/delete at head Usually \(O(n)\) because items shift Usually \(O(1)\)
Insert/delete after known node Usually \(O(n)\) because items shift Usually \(O(1)\)
Search by value Usually \(O(n)\) if unsorted Usually \(O(n)\)
Memory overhead Low per item Extra link field in each node
Memory locality Good Often weaker because nodes may be scattered

Time/Space Analysis

The table above summarizes the most important asymptotic costs. The main difference is that arrays support direct index computation, while linked structures support local rewiring of links once the relevant node is already known.

Array access: Accessing a[i] takes \(O(1)\) time because the position can be computed directly from the base location and the index.

Array insertion/deletion: Inserting or deleting at position pos may require shifting all items after pos. In the worst case this is \(O(n)\) time.

Linked insertion/deletion: Inserting or deleting at the head, or after a known node, takes \(O(1)\) time because only a constant number of links change.

Linked searching: Searching a linked structure takes \(O(n)\) time in the worst case because the algorithm may need to follow links through every node.

Extra space: An array representation usually has little per-item overhead, though resizable arrays may reserve unused capacity. A linked representation stores at least one extra link per node, so it uses \(O(n)\) extra link storage for \(n\) items.

Reading Comprehension Questions

  1. Linear Order: What does it mean for a structure to be linear?
  2. Array Indexing: Why can an array access item i in \(O(1)\) time?
  3. Array Shifting: Why can inserting near the front of an array take \(O(n)\) time?
  4. Node Fields: What two fields does a singly linked node usually store?
  5. Head Insertion: What links must change when inserting a new node at the head?
  6. Delete After: Why does deleteAfter(node) require access to the node before the one being deleted?
  7. Search: Why is searching by value usually \(O(n)\) for both arrays and linked structures?
  8. Tradeoff: Give one advantage of arrays and one advantage of linked structures.
  1. Answer: Its items are arranged in a sequence, so ideas such as first, last, before, after, and next make sense.
  2. Answer: The location of item i can be computed directly from the base location and the index.
  3. Answer: Items after the insertion point must be shifted to make room while preserving order.
  4. Answer: It stores the data item and a link, often called next, to the next node.
  5. Answer: The new node's next link points to the old head, and head is updated to point to the new node.
  6. Answer: To remove a node from a singly linked structure, the previous node's next link must be changed to bypass the removed node.
  7. Answer: Without extra ordering or indexing information, the algorithm may have to inspect every item before finding the value or concluding it is absent.
  8. Answer: Arrays provide fast indexed access. Linked structures can insert or delete at the head, or after a known node, by changing only a few links.

In-Class Activities

  1. Array Shift Trace: Start with [12, 7, 19, 4, 15]. Insert 10 at index 1 by showing each shift.
  2. Node Cards: Give students index cards representing nodes. Each card stores a value and an arrow to the next card. Practice inserting a new head card.
  3. Delete After by Hand: Draw 12 -> 7 -> 19 -> 4. Delete the node after 7 and show exactly which link changes.
  4. Search Race: Compare searching for 4 in an array diagram and in a linked diagram. Identify what information is available at each step.
  5. Representation Choice: For each scenario, decide whether an array or linked representation is more natural: frequent index lookup, frequent head insertion, compact storage, and unknown final size.
  6. Code Reading: Give students the insertAfter code and ask them to explain why the order of assignments matters.
  7. Broken Links: Present an incorrect linked insertion that loses part of the list. Students identify the lost reference and repair the code.
  8. Cost Sorting: Put operation cards into buckets labeled \(O(1)\), \(O(n)\), and "depends on representation." Discuss disagreements.
