Lists

Overview

A list stores values in a specific order. Unlike a stack or queue, a list is not restricted to one active end or one removal rule. Instead, each value has a position, usually numbered from 0 through n - 1, where n is the number of values currently stored. The position of a value is called its index.

For example, the list [12, 4, 18, 7] has size 4. The value at index 0 is 12, the value at index 1 is 4, the value at index 2 is 18, and the value at index 3 is 7. The list order is part of the abstraction: changing the order changes the list.

A list is an abstract data type. The abstraction describes what operations are available, not how the values are stored. A program using a list may ask for the value at an index, replace a value, append a new value at the end, insert a value into the middle, or remove a value from a position. The implementation decides how to carry out those operations.

This page compares two common implementations of the same list idea. An array-based list stores the values in contiguous array positions. This makes indexed access fast, because the implementation can jump directly to position i. The tradeoff is that inserting or removing near the front or middle requires shifting values to preserve the list order.

A singly linked list with a tail pointer stores each value in a node. Each node points to the next node, the list stores a head reference to the first node, and the tail reference points to the last node. The tail reference makes appending at the end constant time, but indexed access is slower because the implementation must follow links from the head until it reaches the requested position.

The important point is that both representations store the same logical list. The operations should have the same meaning for the user of the list, even though the implementation details and operation costs are different. This is the central distinction between an abstract data type and a data-structure implementation.

Core Operations

A list stores values in a definite order. Unlike a stack or queue, a list allows access by position. If a list has \(n\) values, its valid indices are 0 through n - 1.

Also unlike stacks and queues, there is no definitive list of core operations. Different languages and libraries provide different operations, and the same operation may have different names in different contexts. The operations described below are a common set of core operations that cover the main ideas of list manipulation. The table below gives the operation names and descriptions, along with common alternative names.

The most important naming convention in this chapter is the distinction between remove(index) and delete(value). The operation remove(index) removes by position, while delete(value) removes the first matching value. Some libraries overload one name for both ideas, but keeping the names separate helps avoid ambiguity.

General Policies

Several operations require either a valid position or a nonempty list. The operations first(), last(), removeFirst(), and removeLast() require the list to contain at least one value. If the list is empty, a real implementation should handle the case with a documented policy, such as throwing an exception, returning a special value, or reporting failure without changing the list.

The indexed operations also need bounds checks. For get(index), set(index, value), and remove(index), the valid indices are 0 through size() - 1. For insert(index, value), the valid insertion positions are 0 through size(), since inserting at size() adds the new value after the current last value.

If a searched value appears more than once, this chapter uses the first occurrence unless otherwise stated. Thus indexOf(value) returns the index of the first matching value, or -1 if there is no match, and delete(value) deletes the first matching value.

Operation Categories

The operations above can be grouped by what they ask the list to do. End operations work with the first or last value. Indexed operations work with a position. Search operations look for a value. Status operations report or reset the state of the list.

End Operations

End operations are useful because stacks, queues, and deques can all be described using restricted combinations of list operations. A stack uses one end, a queue uses one end for insertion and the other end for removal, and a deque allows insertion and removal at both ends.

Indexed Operations

Indexed operations emphasize one of the main differences between the two implementations studied on this page. An array-based list can jump directly to an index, while a linked list usually has to traverse from the head to reach the same position.

Search and Deletion by Value

Search operations look for a value rather than going directly to a known index. Unless the list is stored in some special searchable form, these operations usually scan values from the beginning until the value is found or the end is reached.

Status and Utility Operations

Status and utility operations keep the rest of the interface consistent. For example, after clear(), size() should return 0, isEmpty() should return true, and end operations should follow the implementation's documented policy for an empty list.

Implementation 1: Array-Based List

Basics

An array-based list stores the logical list in a backing array. The implementation keeps two related quantities: size, the number of meaningful values currently in the list, and capacity, the number of slots in the backing array. The list values occupy positions A[0] through A[size - 1]. Positions from A[size] through A[capacity - 1] are unused storage.

For example, the logical list [12, 4, 18, 7] might be stored in an array of capacity 6. The first four cells store the list values. The remaining two cells are available for future insertions or additions.

Visual Representation of an Array-Based List

The unused cells are part of the array, but they are not part of the logical list. A call to size() returns 4, not 6. The extra capacity exists so that some future additions can be performed without immediately allocating a larger array.

The central invariant is that the logical list is stored contiguously starting at index 0. This invariant makes indexed access simple: the value at list index i is stored directly in A[i]. The cost is that insertions and removals in the middle must shift values to keep the list contiguous.

The version described here is a dynamic array: when the backing array fills up, the implementation allocates a larger array, copies the existing values into it, and then continues the operation. A common resizing rule is to double the capacity when the array is full.

How the Operations Work

The implementation stores an array A, an integer size, and the current capacity A.length. It is often unnecessary to store capacity separately, since the array length already records it.

size, isEmpty, and clear

size() returns the value of the size variable. isEmpty() checks whether size == 0. clear() sets size to 0. In languages with reference types and garbage collection, clear() may also set the formerly used array cells to null so that unused objects can be reclaimed.

first, last, get, and set

These operations do not move values. first() returns A[0], and last() returns A[size - 1], assuming the list is nonempty. get(index) returns A[index], and set(index, value) replaces A[index] with value. The indexed operations must first check that index is between 0 and size - 1.

addLast

addLast(value) places the new value in the first unused position, A[size], and then increments size. If the array is already full, the operation first resizes the backing array. When no resize is needed, addLast performs a constant amount of work.

addFirst and insert

addFirst(value) is the same as insert(0, value). More generally, insert(index, value) first checks that index is between 0 and size. If the backing array is full, it resizes. Then it shifts values at positions index through size - 1 one position to the right, writes the new value into A[index], and increments size.

The shifting must proceed from right to left. If the implementation shifted from left to right, it would overwrite values before copying them to their new positions.

removeFirst, removeLast, and remove

removeLast() removes and returns A[size - 1], then decrements size. No shifting is needed. In contrast, removeFirst() is the same as remove(0), so every remaining value must shift one position left.

More generally, remove(index) first checks that index is between 0 and size - 1. It saves the value at A[index], shifts later values one position left, decrements size, and returns the saved value.

contains, indexOf, and delete

Search operations scan the array from left to right through the logical portion of the list. The operation indexOf(value) returns the first index whose value matches, or -1 if no match is found. contains(value) can be implemented by checking whether indexOf(value) != -1. delete(value) can be implemented by finding the first matching index and then removing that index.

Array-Based List Pseudocode

The following pseudocode assumes a backing array A and an integer size. The helper operation resize() creates a larger backing array and copies the current logical values into it. 

isEmpty():
    return size == 0

size():
    return size

clear():
    size = 0

first():
    if isEmpty():
        report empty-list error and stop
    return A[0]

last():
    if isEmpty():
        report empty-list error and stop
    return A[size - 1]

get(index):
    if index < 0 or index >= size:
        report invalid index and stop
    return A[index]

set(index, value):
    if index < 0 or index >= size:
        report invalid index and stop
    A[index] = value

addLast(value):
    if size == A.length:
        resize()
    A[size] = value
    size = size + 1

addFirst(value):
    insert(0, value)

insert(index, value):
    if index < 0 or index > size:
        report invalid index and stop
    if size == A.length:
        resize()
    for j = size down to index + 1:
        A[j] = A[j - 1]
    A[index] = value
    size = size + 1

removeLast():
    if isEmpty():
        report empty-list error and stop
    value = A[size - 1]
    size = size - 1
    return value

removeFirst():
    return remove(0)

remove(index):
    if index < 0 or index >= size:
        report invalid index and stop
    value = A[index]
    for j = index to size - 2:
        A[j] = A[j + 1]
    size = size - 1
    return value

indexOf(value):
    for i = 0 to size - 1:
        if A[i] == value:
            return i
    return -1

contains(value):
    return indexOf(value) != -1

delete(value):
    index = indexOf(value)
    if index == -1:
        return false
    remove(index)
    return true

resize():
    newCapacity = max(1, 2 * A.length)
    B = new array of length newCapacity
    for i = 0 to size - 1:
        B[i] = A[i]
    A = B

Implementation Analysis

The cost of an array-based list depends on whether the operation can use direct indexing or whether it must move or scan many values.

  • size, isEmpty: \(O(1)\). Each checks or returns a stored variable.
  • first, last: \(O(1)\). Each reads one array cell after checking that the list is nonempty.
  • get(index), set(index, value): \(O(1)\). After a bounds check, the implementation accesses A[index] directly.
  • addLast(value): \(O(1)\) if there is unused capacity. If the array is full, resizing takes \(O(n)\). With geometric resizing, a sequence of additions has amortized \(O(1)\) time per addLast.
  • addFirst(value): \(O(n)\), because all existing values must shift one position right.
  • insert(index, value): \(O(n)\) in the worst case. Inserting near the front shifts many values. Inserting at the end shifts none, although it may still trigger a resize.
  • removeLast(): \(O(1)\). It removes the final logical value without shifting.
  • removeFirst(): \(O(n)\), because all remaining values shift one position left.
  • remove(index): \(O(n)\) in the worst case. Removing near the front shifts many later values.
  • indexOf(value), contains(value): \(O(n)\) in the worst case, because the value may be absent or appear only at the end.
  • delete(value): \(O(n)\) in the worst case. It may scan the whole list and, if it finds the value, shift later values left.
  • clear(): \(O(1)\) if it only sets size = 0. It can be \(O(n)\) if the implementation also clears old references from the backing array.
Storage Used

An array-based list uses \(O(c)\) space, where \(c\) is the current capacity of the backing array. If the list stores \(n\) values, then \(c - n\) array cells are unused capacity. With the usual doubling strategy, the capacity remains within a constant factor of the number of stored values after the list has grown, so the storage is \(O(n)\) in terms of the logical list size. The implementation also uses \(O(1)\) extra space for variables such as size and loop indices.

Tradeoffs

  • Array-based lists provide fast indexed access. The value at index i is stored directly in A[i].
  • Appending at the end is efficient in practice because resizing happens only occasionally when capacity grows geometrically.
  • Insertions and removals near the front or middle are expensive because values must shift to keep the list contiguous.
  • The backing array may contain unused capacity, so the implementation can use more space than the logical list size alone requires.
  • Array-based lists are usually cache-friendly because values are stored in adjacent array cells.
  • Resizing preserves the logical list but can invalidate low-level references or pointers to the old backing array in languages that expose such details.
  • This representation is a strong default when a program frequently uses indexing, scanning, or appending at the end.

Implementation 2: Singly Linked List with Tail

Basics

A singly linked list stores each value in a separate node. Each node stores a value and a next reference to the following node. The list itself stores a head reference to the first node. In this implementation, it also stores a tail reference to the last node and a size variable.

The tail reference is the important addition compared with a singly linked list that stores only head. With tail, addLast(value) can attach a new node directly after the current last node. Without tail, adding at the end would require traversing the whole list to find the last node.

For example, the logical list [12, 4, 18, 7] can be represented as a chain of four nodes. The head reference points to the node storing 12, and the tail reference points to the node storing 7. The final node's next reference is null.

Visual Representation of a Singly Linked List with Tail

The logical order is determined by the links, not by adjacent memory locations. Following next references from head visits the values in list order.

The main invariant is that head points to the first node, tail points to the last node, and following next references from head visits all nodes in order and then reaches null. If the list is empty, then both head and tail should be null, and size should be 0.

How the Operations Work

The implementation stores references head and tail, along with an integer size. The head reference supports efficient operations at the front. The tail reference supports efficient access to the last value and efficient addition at the end.

size, isEmpty, and clear

size() returns the stored size variable. isEmpty() checks whether size == 0, or equivalently whether head == null. clear() sets head and tail to null and sets size to 0.

first and last

first() returns head.value, assuming the list is nonempty. last() returns tail.value. Both are constant-time operations because the implementation stores direct references to both ends of the list.

addFirst

addFirst(value) creates a new node whose next reference points to the old head. Then head is updated to point to the new node. If the list was empty before the operation, the new node is both the first and last node, so tail must also point to it. Finally, size is incremented.

addLast

addLast(value) creates a new node whose next reference is null. If the list is empty, both head and tail point to the new node. Otherwise, the old tail.next is set to the new node, and then tail is updated to the new node. This is the operation that most clearly benefits from storing a tail reference.

get and set

A singly linked list cannot jump directly to index i. To perform get(index) or set(index, value), the implementation checks that the index is valid, starts at head, and follows next references until it reaches the node at that position.

insert

insert(index, value) first checks that index is between 0 and size. If index == 0, the operation is addFirst(value). If index == size, the operation is addLast(value). Otherwise, the implementation traverses to the node at position index - 1, inserts the new node after it, and increments size.

The order of reference updates matters. The new node should first point to the old successor. Then the previous node can point to the new node. Reversing those steps can lose access to the rest of the list.

removeFirst, removeLast, and remove

removeFirst() saves head.value, moves head to head.next, decrements size, and returns the saved value. If the removed node was the only node, the list becomes empty, so tail must also be set to null.

removeLast() is more expensive in a singly linked list. Even though tail points to the last node, the implementation also needs the node before the tail so it can change that node's next reference to null. Since nodes only point forward, the implementation must traverse from head to find the predecessor of tail.

More generally, remove(index) first checks that index is between 0 and size - 1. If index == 0, the operation is removeFirst(). Otherwise, the implementation traverses to the node at position index - 1, bypasses the node after it, updates tail if the removed node was the last node, decrements size, and returns the removed value.

contains, indexOf, and delete

Search operations traverse from head toward the end of the list. The operation indexOf(value) returns the first index whose node stores value, or -1 if no match is found. contains(value) can be implemented by checking whether indexOf(value) != -1. delete(value) searches for the first node storing value and removes it if it exists.

Linked List Pseudocode

The following pseudocode assumes a node type with fields value and next. The list stores head, tail, and size. 

isEmpty():
    return size == 0

size():
    return size

clear():
    head = null
    tail = null
    size = 0

first():
    if isEmpty():
        report empty-list error and stop
    return head.value

last():
    if isEmpty():
        report empty-list error and stop
    return tail.value

addFirst(value):
    newNode = new Node(value)
    newNode.next = head
    head = newNode
    if tail == null:
        tail = newNode
    size = size + 1

addLast(value):
    newNode = new Node(value)
    if isEmpty():
        head = newNode
        tail = newNode
    else:
        tail.next = newNode
        tail = newNode
    size = size + 1

nodeAt(index):
    cur = head
    for i = 0 to index - 1:
        cur = cur.next
    return cur

get(index):
    if index < 0 or index >= size:
        report invalid index and stop
    return nodeAt(index).value

set(index, value):
    if index < 0 or index >= size:
        report invalid index and stop
    nodeAt(index).value = value

insert(index, value):
    if index < 0 or index > size:
        report invalid index and stop
    if index == 0:
        addFirst(value)
    else if index == size:
        addLast(value)
    else:
        prev = nodeAt(index - 1)
        newNode = new Node(value)
        newNode.next = prev.next
        prev.next = newNode
        size = size + 1

removeFirst():
    if isEmpty():
        report empty-list error and stop
    value = head.value
    head = head.next
    size = size - 1
    if head == null:
        tail = null
    return value

removeLast():
    if isEmpty():
        report empty-list error and stop
    if size == 1:
        return removeFirst()
    prev = nodeAt(size - 2)
    value = tail.value
    prev.next = null
    tail = prev
    size = size - 1
    return value

remove(index):
    if index < 0 or index >= size:
        report invalid index and stop
    if index == 0:
        return removeFirst()
    prev = nodeAt(index - 1)
    oldNode = prev.next
    value = oldNode.value
    prev.next = oldNode.next
    if oldNode == tail:
        tail = prev
    size = size - 1
    return value

indexOf(value):
    cur = head
    index = 0
    while cur != null:
        if cur.value == value:
            return index
        cur = cur.next
        index = index + 1
    return -1

contains(value):
    return indexOf(value) != -1

delete(value):
    if isEmpty():
        return false
    if head.value == value:
        removeFirst()
        return true

    prev = head
    cur = head.next
    while cur != null:
        if cur.value == value:
            prev.next = cur.next
            if cur == tail:
                tail = prev
            size = size - 1
            return true
        prev = cur
        cur = cur.next
    return false

Implementation Analysis

The cost of a singly linked list with a tail reference depends on whether the operation works at a known end of the list or must traverse nodes to find a position or value.

  • size, isEmpty: \(O(1)\). Each checks or returns a stored variable.
  • first, last: \(O(1)\). The implementation stores direct references to both the first and last nodes.
  • addFirst(value): \(O(1)\). It creates one node and changes a constant number of references.
  • addLast(value): \(O(1)\). The tail reference lets the implementation attach a new node at the end without traversal.
  • get(index), set(index, value): \(O(n)\) in the worst case, because reaching index index may require following many links from head.
  • insert(index, value): \(O(n)\) in the worst case. Inserting at the front or back is \(O(1)\), but inserting at a general index requires traversal to the predecessor.
  • removeFirst(): \(O(1)\). It moves head to the next node and possibly clears tail.
  • removeLast(): \(O(n)\). The implementation must find the node before tail, which requires traversal in a singly linked list.
  • remove(index): \(O(n)\) in the worst case. Removing the first value is \(O(1)\), but removing at a general index requires traversal to the predecessor.
  • indexOf(value), contains(value): \(O(n)\) in the worst case, because the value may be absent or stored only at the last node.
  • delete(value): \(O(n)\) in the worst case. It may have to search the whole list before deleting, or before determining that the value is absent.
  • clear(): \(O(1)\) if it only sets head = null, tail = null, and size = 0. In a language with manual memory management, freeing all nodes would take \(O(n)\).
Storage Used

A linked list uses \(O(n)\) space for \(n\) stored values. Each value is stored inside a node, and each node also stores a next reference. The list itself stores \(O(1)\) extra information: head, tail, and size.

Tradeoffs

  • The linked implementation does not need unused array capacity; it creates one node for each stored value.
  • addFirst, addLast, removeFirst, first, and last are constant-time operations.
  • removeLast is still linear time because a singly linked list cannot move backward from tail to the previous node.
  • Indexed access is slow compared with an array-based list because the implementation must follow links to reach a position.
  • Insertion or removal at a known node can be efficient, but the List ADT operations are index-based, so finding the right node is often part of the cost.
  • Each node has reference overhead, so a linked list usually uses more memory per stored value than an array-based list.
  • Linked nodes may be scattered in memory, making traversal less cache-friendly than scanning an array.
  • This representation is most useful when a program performs frequent operations at the front or back and does not rely heavily on indexed access.

Implementation Cost Summary

The two implementations represent the same List ADT, but they make different operations efficient. The array-based list is strongest when the program needs indexed access, indexed updates, scanning, or adding at the end. The singly linked list with tail is strongest for operations at the front and for adding or reading at the back.

Library Implementations

Most programming languages provide one or more built-in or standard-library list-like structures. These libraries may use different names for the same basic operations, and they may choose different underlying representations.

Language Common Structure Likely Representation Notes
Java ArrayList<E> Dynamic array Fast indexed access and amortized constant-time addition at the end.
Java LinkedList<E> Doubly linked list Supports both list and deque operations, but indexed access is still linear time.
C++ std::vector<T> Dynamic array The usual default sequence container when fast indexing is needed.
C++ std::list<T> Doubly linked list Efficient insertion and removal when an iterator already identifies the position.
C++ std::forward_list<T> Singly linked list Uses less link storage than std::list, but supports only forward traversal.
Python list Dynamic array Despite the name, Python's built-in list is array-based, not linked.
Python collections.deque Deque-oriented block structure Better than list for frequent additions and removals at both ends.

In practice, dynamic arrays are often the default choice for list-like data because they provide fast indexing, compact storage, and good performance when scanning. Linked lists are still important for understanding references and for workloads where positions are already known and local relinking is the main operation.

Applications

Lists are one of the most common ways to store a collection of values when the order matters. They are more flexible than stacks and queues because they support access by position, not just access at one or two restricted ends. The best implementation depends on how the list is used.

  • General-purpose ordered collections: Lists are used whenever a program needs to keep values in a meaningful order, such as names in a roster, assignments in a gradebook, songs in a playlist, or messages in a conversation.
  • Indexed data: Array-based lists are useful when positions matter and the program frequently calls operations such as get(index) and set(index, value). Many tables, dynamic programming arrays, and simulation states rely on efficient indexed access.
  • Accumulating results: A dynamic array is often used to collect results when the final number of values is not known ahead of time. The program can repeatedly call addLast(value) and allow the list to grow as needed.
  • Stacks, queues, and deques: These structures can be implemented using a restricted set of list operations. For example, a stack can use one end of a list, a queue can add at one end and remove at the other, and a deque can allow additions and removals at both ends.
  • Graph representations: Many graph algorithms represent a graph using adjacency lists. Each vertex stores a list of its neighbors. Depending on the application, these neighbor lists might be array-based, linked-based, or implemented by a library container.
  • Local insertion and deletion: Linked lists are useful when a program already has a reference to the relevant location and needs to insert or remove nearby nodes. This appears in some low-level data structures, memory-management systems, and iterator-based container operations.
  • Maintaining changing sequences: Lists are useful when the order changes over time, such as editing a sequence of tasks, maintaining a list of active events in a simulation, or storing a mutable collection of objects in a game or interface.

In practice, array-based lists are often the default choice because they provide fast indexing, compact storage, and efficient scanning. Linked lists are still important because they illustrate reference-based storage and because they can be effective when local relinking, rather than indexed access, is the central operation.

Comparisons and Tradeoffs

The List ADT describes what operations are available, but the implementation determines which operations are efficient. The array-based list and the singly linked list with tail both store the same kind of logical sequence, but they organize the data in very different ways.

Indexing vs. Traversal

The biggest advantage of an array-based list is direct indexed access. Once an index is checked, get(index) and set(index, value) can go directly to A[index]. A linked list cannot do this because the location of the \(i\)th value is not computed from the index. The implementation must start at head and follow next references until it reaches the desired node.

Shifting vs. Relinking

Array-based lists keep all logical values in consecutive array positions. This makes indexing fast, but it means that insertion or removal near the front may require many values to shift. Linked lists avoid shifting values. Once the relevant node or predecessor is known, an insertion or removal changes only a few references. However, if the operation is specified by index or by value, the linked list may still spend linear time finding the correct location.

Front and Back Operations

The two implementations behave differently at the ends of the list. In a singly linked list with a tail reference, addFirst(value), removeFirst(), first(), addLast(value), and last() are all constant-time operations. The exception is removeLast(), which is linear time because a singly linked list cannot move backward from tail to the previous node.

In an array-based list, last(), removeLast(), and usually addLast(value) are efficient. But addFirst(value) and removeFirst() are expensive because they require shifting all existing values.

Memory Use

An array-based list may allocate more cells than it currently needs. This unused capacity is intentional: it allows several future calls to addLast(value) before another resize is needed. A linked list does not keep unused array slots, but each node stores an extra next reference in addition to the value.

Practical Performance

Even when two operations have the same Big-O running time, their practical performance can differ. Array-based lists are usually cache-friendly because neighboring values are stored near each other in memory. Linked lists may scatter nodes throughout memory, so traversal can be slower in practice even when the asymptotic cost is the same.

Choosing an Implementation

An array-based list is usually the better default when a program frequently uses indexing, scanning, or adding at the end. A linked list is more appropriate when the program frequently updates the front of the list or already has references to the nodes where insertions and deletions should occur. The important lesson is not that one representation is always better, but that the right representation depends on the operations the program performs most often.

Variations and Extensions

The two implementations in this chapter are not the only ways to represent a list. They are useful baseline designs because they show the main tradeoff between direct indexing and linked traversal. Many real data structures adjust these ideas to improve particular operations or support additional behavior.

Fixed-Size Array Lists

A fixed-size array list uses an array with a maximum capacity and does not resize. This makes the implementation simpler and gives predictable memory use, but addLast(value) or insert(index, value) can fail when the array is full. Fixed-size lists are useful when the maximum number of values is known ahead of time or when resizing is not allowed.

Dynamic Arrays with Shrinking

The array-based implementation in this chapter grows when the backing array is full. Some implementations also shrink the backing array when the list becomes much smaller than its capacity. Shrinking can save memory, but it must be done carefully. If the array shrinks too aggressively, a program that alternates between adding and removing values may spend too much time repeatedly resizing.

Doubly Linked Lists

A doubly linked list gives each node two links: next and prev. The next link points toward the following node, and the prev link points toward the previous node. This extra link allows movement in both directions and makes it possible to remove a known node without first finding its predecessor.

Doubly linked lists also make removeLast() efficient when the list stores a tail reference, because the implementation can move backward from the tail to the previous node. The tradeoff is extra memory per node and more reference updates during insertion and deletion.

Circular Linked Lists

In a circular linked list, the final node points back to the first node instead of pointing to null. This can be useful for round-robin scheduling, repeated cycling through values, or structures where there is no natural end. Circular lists require careful stopping conditions during traversal, since following links never reaches null.

Sentinel Nodes

A sentinel node is a special dummy node that does not store a real list value. Sentinels can simplify boundary cases by ensuring that there is always a node before the first real value or after the last real value. This can make insertion and deletion code more uniform, but it adds an extra concept that the implementation must keep separate from the actual data.

Sorted Lists

A sorted list keeps its values in increasing or decreasing order. Instead of inserting a new value at an arbitrary position, the implementation searches for the correct position and inserts the value there. Searching for a value can stop early once the scan passes the position where the value would have appeared, but insertion may still require shifting values in an array-based list or traversing links in a linked list.

Unrolled Linked Lists

An unrolled linked list stores several values in each node instead of storing only one value per node. This reduces the number of links and can improve cache behavior while still allowing linked-style growth. The tradeoff is that insertion and deletion inside a node may require shifting values within that node.

Skip Lists

A skip list augments a sorted linked structure with extra forward links that skip over many values. These extra links make search, insertion, and deletion much faster on average than scanning a basic linked list. Skip lists are more advanced than the list implementations in this chapter, but they show how adding structure can improve search performance.

These variations reinforce the main theme of the chapter: a list is an abstract sequence, while an implementation is a particular set of choices about storage, access, and update costs. Different choices are useful for different workloads.

Common Pitfalls

List implementations are conceptually simple, but many errors come from boundary cases and from confusing the abstract list with its underlying representation. The following pitfalls are especially common when implementing array-based lists or singly linked lists.

Confusing Size and Capacity

In an array-based list, size is the number of meaningful values in the list, while capacity is the number of allocated array cells. Operations such as get(index), set(index, value), and remove(index) should check indices against size, not against the array's capacity. An unused array cell is not part of the list.

Using the Wrong Bounds for Insert

The operation insert(index, value) has slightly different bounds than get(index), set(index, value), and remove(index). For get, set, and remove, the valid indices are 0 through size - 1. For insert, the valid positions are 0 through size. Inserting at size means adding after the current last value.

Shifting in the Wrong Direction

In an array-based list, inserting requires shifting values to the right before writing the new value. That shift must proceed from right to left so that values are not overwritten before being copied. Removing shifts values left, so that shift proceeds from left to right.

Forgetting to Resize Before Inserting

A dynamic array must make room before writing a new value into a full backing array. This matters for both addLast(value) and insert(index, value). If the implementation shifts values or writes into A[size] before resizing, it may access a position outside the array.

Leaving Stale References in an Array

After removing an element from an array-based list, the old last logical position is no longer part of the list. In languages with garbage collection, it is often useful to set that array cell to null when the stored values are references. This prevents the array from accidentally keeping an object alive after it has been removed from the list.

Losing Part of a Linked List

In a linked list, the order of reference updates matters. When inserting a node after another node, the new node should first point to the old successor. Then the previous node can point to the new node. If the old link is overwritten too early, the rest of the list can become unreachable.

Forgetting to Update Tail

A singly linked list with a tail reference must keep tail consistent with the actual last node. If an operation adds to an empty list, both head and tail should point to the new node. If an operation removes the last remaining node, both should become null. If an operation removes the current tail, tail must move to the previous node.

Assuming Tail Makes Every Back Operation Constant Time

A tail reference makes last() and addLast(value) constant time, but it does not make removeLast() constant time in a singly linked list. To remove the last node, the implementation must also find the node before it. Since nodes only point forward, that search starts at head and takes linear time in the worst case.

Confusing Removal by Position and Removal by Value

In this chapter, remove(index) removes by position, while delete(value) removes the first matching value. Mixing these up can produce subtle errors, especially when the list stores integers. For example, remove(3) means remove the value at index 3, not remove the value 3.

Ignoring Empty-List Cases

Operations such as first(), last(), removeFirst(), and removeLast() require the list to contain at least one value. A complete implementation should define what happens when these operations are called on an empty list, rather than accidentally reading invalid array positions or dereferencing null.

Summary

A list is an ordered collection of values with positions. Unlike a stack or queue, a list allows operations that refer directly to an index, such as get(index), set(index, value), insert(index, value), and remove(index). Lists also support operations at the ends, search operations, and utility operations such as size(), isEmpty(), and clear().

The same List ADT can be implemented in different ways. An array-based list stores values in consecutive positions of a backing array. This makes indexed access and update fast, but insertions and removals near the front or middle may require shifting many values. A dynamic array can grow by allocating a larger backing array and copying the current values into it.

A singly linked list with a tail reference stores values in nodes connected by next references. The head reference gives access to the first node, and the tail reference gives access to the last node. This makes several end operations efficient, including addFirst(value), removeFirst(), first(), addLast(value), and last(). However, indexed access requires traversal, and removeLast() is still linear time because a singly linked list cannot move backward from the tail.

The main tradeoff is between direct indexing and local relinking. Array-based lists are usually best when a program frequently indexes, scans, or appends. Linked lists are useful when a program frequently works near known nodes or updates the front of the structure. Neither representation is always better; the right choice depends on the operations performed most often.

  • A list stores values in order and identifies them by position.
  • remove(index) removes by position; delete(value) removes the first matching value.
  • Array-based lists provide \(O(1)\) indexed access and amortized \(O(1)\) addition at the end.
  • Array-based insertions and removals can take \(O(n)\) time because values may need to shift.
  • Singly linked lists with a tail pointer support efficient front operations and efficient addition at the back.
  • Linked lists require traversal for indexed access, indexed update, search, and most middle operations.
  • Implementation details such as resizing, bounds checks, reference updates, and empty-list cases are essential for correctness.
