Linked Lists

Overview

A linked list stores a sequence of values in a chain of nodes. Each node stores a value and one or more links to other nodes. In a singly linked list, each node stores a value and a next reference to the following node. The list itself stores a head reference to the first node. Some implementations also store a tail reference to the last node.

The logical order of a linked list is determined by the links, not by adjacent memory locations. The first node is reached through head. The second node is reached through head.next. The list ends when a next reference is null.

We will usually write the list above as 14 -> 8 -> 31 -> 5. This notation describes the logical sequence, not the physical memory layout.

Linked lists are most useful when a program needs local insertions and deletions and already has a reference to the relevant place in the list. They are less useful when the program frequently needs the item at index i, because reaching that item requires following links from a known starting point.

Core Operations

A linked list represents an ordered sequence, but unlike a stack or queue, it is not defined by one strict access rule. Different implementations expose different operations. The following table lists the most common operations for a singly linked list. The essential distinction is whether the operation already has a reference to the relevant node or must first search for it.

Operation Description
isEmpty() Report whether head == null.
front() Return the value stored at the head without removing it. This requires a defined empty-list policy.
pushFront(value) Create a new first node storing value and make head point to it.
popFront() Remove and return the first value. This changes head to the second node.
pushBack(value) Add value at the end. This is constant time only if the implementation stores tail.
insertAfter(node, value) Given a reference to a node already in the list, insert a new node immediately after it.
deleteAfter(node) Given a reference to a node, remove the node immediately after it, if one exists.
find(value) Traverse from head until a node storing value is found or the end is reached.
deleteFirst(value) Remove the first node storing value. This usually requires a traversal with two references.
get(index) Return the value at position index by following links from the head.
size() Return the number of values. This is constant time only if the implementation maintains a count.

Some lists are designed as small building blocks for stacks or queues and expose only front and back operations. Other lists expose more general operations such as insertion after a node, deletion by value, or indexed access. Regardless of the interface, the implementation must keep the chain of links consistent.

Traversal and Search

Traversal begins at head and repeatedly follows next references until reaching null. Search is just traversal with a stopping condition. 

find(value):
    cur = head
    while cur != null:
        if cur.value == value:
            return cur
        cur = cur.next
    return null

If the value is absent or appears only at the end, the search examines every node. This is why search in a linked list is usually linear time.

Insert at the Front

Inserting at the front creates a new node whose next reference points to the old head. Then head is updated to point to the new node. If the list was empty and the implementation stores tail, then tail must also point to the new node.

Insert After a Known Node

Inserting after a known node requires two reference changes. The new node must first point to the old successor; then the known node can point to the new node. The order matters because overwriting the old link too early can lose access to the rest of the list. 

insertAfter(node, value):
    if node == null:
        report invalid position and stop
    newNode = new Node(value)
    newNode.next = node.next
    node.next = newNode

Delete After a Known Node

Deleting after a known node removes the successor by bypassing it. The operation needs the predecessor because the predecessor stores the link that must change. 

deleteAfter(node):
    if node == null or node.next == null:
        report invalid position and stop
    oldNode = node.next
    node.next = oldNode.next
    return oldNode.value
Example Trace of Linked List Operations

Start with an empty list and perform the following operations: pushFront(8), pushFront(14), pushBack(31), insertAfter(node storing 8, 99), deleteAfter(node storing 8), popFront().

Operation List Afterward Return Value

pushFront(14) 14 -> 8 none
pushBack(31) 14 -> 8 -> 31 none
insertAfter(node storing 8, 99) 14 -> 8 -> 99 -> 31 none

Implementation Options

Linked lists can be implemented in several closely related ways. This page focuses on singly linked lists, first without a tail reference and then with a tail reference. A doubly linked list is treated as a variation later because it changes the node structure by adding a backward link.

Implementation 1: Singly Linked List with Head

Basics

The simplest singly linked list stores a head reference and, optionally, a count variable. Each node stores a value and a next reference. If the list is empty, head == null. If the list is nonempty, following next links from head visits every node in order and eventually reaches null.

This representation is especially good for operations at the front. It can also insert or delete after a known node in constant time. However, operations at the end require a traversal unless some other reference already points near the end.

Visual Representation of a Singly Linked List

The list 14 -> 8 -> 31 has head pointing to the node storing 14. The final node's next reference is null.

How the Operations Work

isEmpty

isEmpty() checks whether head == null. This works because every nonempty list has a first node, and head must point to that node.

pushFront (insert at head)

pushFront creates a new node, makes the new node's next reference point to the old head, and then updates head to the new node. If a count variable is maintained, it is incremented.

popFront

popFront first checks whether the list is empty. If not, it saves head.value, changes head to head.next, decrements count if needed, and returns the saved value. If the removed node was the only node, then head becomes null.

find (search)

find(value) starts at head and follows next references until it finds a matching value or reaches null. The operation returns a reference to the matching node, not a copy of the value.

insertAfter

insertAfter(node, value) is constant time once node is known. It does not need to move any existing values; it only changes references.

deleteAfter

deleteAfter(node) is also constant time once node is known and has a successor. The predecessor's next reference is changed to skip over the removed node.

size

If the list maintains count, then size() returns count in constant time. Without count, computing the size requires traversing the whole list.

Singly Linked List Pseudocode

The following pseudocode assumes a head reference and a count variable, but no tail reference. 

isEmpty():
    return head == null

pushFront(value):
    newNode = new Node(value)
    newNode.next = head
    head = newNode
    count = count + 1

popFront():
    if isEmpty():
        report underflow and stop
    value = head.value
    head = head.next
    count = count - 1
    return value

find(value):
    cur = head
    while cur != null:
        if cur.value == value:
            return cur
        cur = cur.next
    return null

insertAfter(node, value):
    if node == null:
        report invalid position and stop
    newNode = new Node(value)
    newNode.next = node.next
    node.next = newNode
    count = count + 1

deleteAfter(node):
    if node == null or node.next == null:
        report invalid position and stop
    value = node.next.value
    node.next = node.next.next
    count = count - 1
    return value

size():
    return count

Implementation Analysis

Front operations and updates after a known node take constant time. Searching, indexed access, and end operations take linear time unless extra references or iterators are available.

  • pushFront: \(O(1)\). It creates one node and changes one or two references.
  • popFront: \(O(1)\). It removes the head node by moving head to head.next.
  • insertAfter: \(O(1)\) once the node is known. Finding that node may cost \(O(n)\).
  • deleteAfter: \(O(1)\) once the predecessor is known.
  • find: \(O(n)\). The value may be absent or stored in the last node.
  • get(index): \(O(index)\), which is \(O(n)\) in the worst case.
  • pushBack: \(O(n)\) without a tail reference, because the implementation must find the last node.
  • size: \(O(1)\) if count is maintained, otherwise \(O(n)\).
Storage used:

A singly linked list uses \(O(n)\) space for \(n\) nodes. Each node stores the value and one next reference. The list object itself uses \(O(1)\) extra space for references and counters.

Tradeoffs

  • The implementation is simple and supports constant-time insertion and deletion at the front.
  • Insertion or deletion after a known node is constant time.
  • Finding a node is still linear time.
  • Appending at the end is linear time unless a tail reference is added.
  • The list uses extra reference storage and has weaker memory locality than an array.

Implementation 2: Singly Linked List with Head and Tail

Basics

A singly linked list with both head and tail stores a reference to the first node and a reference to the last node. The main invariant is that head points to the first node, tail points to the last node, and tail.next == null. If the list is empty, both head and tail are null.

The tail reference makes pushBack constant time. It does not make search, indexed access, or deletion of the last node constant time in a singly linked list, because deleting the last node still needs the predecessor of tail.

How the Operations Work

pushBack

pushBack creates a new node whose next reference is null. If the list is empty, both head and tail become the new node. Otherwise, tail.next is set to the new node, and then tail is updated to the new node.

popFront

popFront is mostly the same as before, but it has one additional boundary case. If removing the first node makes the list empty, then tail must also be set to null.

deleteFirst

Deleting the first occurrence of a value requires a traversal. The implementation usually keeps two references, prev and cur. When cur stores the target value, prev.next can be updated to bypass cur. If cur is the tail, then tail must be updated to prev.

Head and Tail Pseudocode

pushBack(value):
    newNode = new Node(value)
    newNode.next = null

    if head == null:
        head = newNode
        tail = newNode
    else:
        tail.next = newNode
        tail = newNode

    count = count + 1

popFront():
    if head == null:
        report underflow and stop

    value = head.value
    head = head.next
    if head == null:
        tail = null
    count = count - 1
    return value

deleteFirst(value):
    if head == null:
        return false

    if head.value == value:
        head = head.next
        if head == null:
            tail = null
        count = count - 1
        return true

    prev = head
    cur = head.next
    while cur != null:
        if cur.value == value:
            prev.next = cur.next
            if cur == tail:
                tail = prev
            count = count - 1
            return true
        prev = cur
        cur = cur.next

    return false

Implementation Analysis

  • pushBack: \(O(1)\). The tail reference gives direct access to the last node.
  • pushFront: \(O(1)\). The head reference gives direct access to the first node.
  • popFront: \(O(1)\). The first node can be removed by updating head.
  • deleteFirst(value): \(O(n)\). The node containing the value may be absent or near the end.
  • deleteBack: \(O(n)\) for a singly linked list. The predecessor of tail must be found.
  • size: \(O(1)\) if count is maintained.
Storage used:

The list still uses \(O(n)\) node space. The extra tail reference uses only \(O(1)\) additional space but can substantially improve append-heavy workloads.

Tradeoffs

  • The tail reference makes appending efficient.
  • The representation is useful for queue implementations, where enqueue occurs at the tail and dequeue occurs at the head.
  • Deleting the last node is still not constant time in a singly linked list.
  • Every operation that changes the first or last node must keep head and tail consistent.

Implementation Cost Summary

Linked list costs depend strongly on whether the relevant node is already known. The update itself may be constant time, while finding the update position may be linear time.

Library Implementations

In everyday programming, linked lists are less common than their textbook prominence might suggest. Standard dynamic arrays are often faster for many workloads because they use contiguous memory and have less per-item overhead. Still, library linked lists are useful when stable node-like positions, frequent local splicing, or deque-style end operations matter.

Language Common Choice Front Operations Back Operations Notes
Java LinkedList<E> addFirst, removeFirst addLast, removeLast Java's LinkedList is a doubly linked list and also implements deque operations.
C++ std::forward_list<T>, std::list<T> push_front, pop_front push_back, pop_back for std::list forward_list is singly linked; list is doubly linked.
Python collections.deque appendleft, popleft append, pop Python has no built-in general linked list class. A deque is the usual library choice for efficient end operations.

In a data structures course, implementing a linked list by hand is still valuable because it makes reference updates, boundary cases, and memory-layout tradeoffs explicit.

Applications

Linked lists are useful when a program benefits from node-level updates rather than array-style shifting. They are also important because many other data structures can be built from linked nodes.

  • Stacks: A linked stack can use the head as the top, making push and pop constant time.
  • Queues: A singly linked list with head and tail references can enqueue at the tail and dequeue at the head in constant time.
  • Adjacency lists: Graphs are often represented by an array of neighbor lists. Linked nodes are one possible representation for each neighbor list.
  • Local splicing: If a program already has references to the relevant nodes, it can insert or remove nodes without shifting a block of values.
  • Hash-table chaining: A bucket can store colliding keys in a linked chain.
  • Sparse symbolic data: Polynomials or sparse vectors can store only meaningful terms as linked nodes.
  • Free lists: Systems code can connect reusable memory blocks or objects with links.
  • Reference education: Linked lists are a useful setting for learning aliasing, null checks, object identity, and pointer updates.

A stack needs insertion and removal at one end. A singly linked list can make the head of the list the top of the stack. Then push becomes pushFront, pop becomes popFront, and peek reads head.value. No tail reference is needed.

Example 2: Using a Linked List as a Queue

A queue needs insertion at one end and removal at the other. A singly linked list can do this efficiently if it stores both head and tail. Enqueue adds after tail, and dequeue removes head. The important boundary case is the transition between empty and one-node lists.

Example 3: Sorted Insertion

To insert into a sorted singly linked list, traverse until finding the first node whose value is greater than the new value. Keep track of the previous node during the traversal. Then insert the new node between prev and cur. The insertion itself is constant time, but finding the position is linear time in the worst case. 

sortedInsert(value):
    if head == null or value <= head.value:
        pushFront(value)
        return

    prev = head
    cur = head.next
    while cur != null and cur.value < value:
        prev = cur
        cur = cur.next

    newNode = new Node(value)
    newNode.next = cur
    prev.next = newNode

Connections and Comparisons

Linked lists are one representation of a sequence. They should be compared not only by Big-O notation but also by memory layout, access patterns, and what information is already available when an operation begins.

  • Linked list vs. array: Arrays provide constant-time indexed access. Linked lists provide constant-time local updates after a known node but require traversal for indexed access.
  • Finding vs. updating: Updating after a known node may be \(O(1)\). Finding that node may be \(O(n)\). Many linked-list mistakes come from ignoring the finding cost.
  • Head-only vs. head-and-tail: A tail reference makes append efficient but does not eliminate the need to search for arbitrary positions.
  • Singly vs. doubly linked: Singly linked lists use one link per node. Doubly linked lists use two links per node and support easier deletion of a known node and reverse traversal.
  • Linked list vs. stack or queue: A linked list is a storage representation. A stack or queue is an ADT with a restricted access rule. Linked nodes can implement either one.
  • Asymptotic vs. practical performance: Linked lists avoid shifting, but pointer chasing and extra allocations often make them slower than dynamic arrays for simple scans and indexed workloads.

Variations and Extensions

Many linked structures change the node layout or boundary conventions to make certain operations easier. These are not separate ideas from linked lists; they are variations on how nodes are connected.

  • Singly linked list: Each node points only forward. This is enough for one-way traversal, stacks, and queues with a tail reference.
  • Doubly linked list: Each node stores both next and prev. This supports bidirectional traversal and constant-time deletion of a known node, but every node stores one extra reference and every update must preserve both directions.
  • Circular linked list: The final node links back to the first node instead of ending at null. This can be useful for round-robin scheduling and cyclic scans.
  • Sentinel-node list: A dummy node can stand before the first real value, after the last real value, or both. Sentinels can reduce boundary cases but require care so that dummy nodes are not treated as data.
  • Unrolled linked list: Each node stores a small array of values. This reduces link overhead and improves locality while preserving some block-level insertion flexibility.
  • Skip list: Nodes have extra forward links at multiple levels. This gives expected logarithmic search, insertion, and deletion and is often presented as a probabilistic alternative to balanced search trees.
  • Intrusive linked list: The link fields are stored inside the objects being linked rather than in separate wrapper nodes. This is common in low-level systems code.
  • Persistent linked list: Updates preserve old versions by sharing unchanged suffixes. This idea is common in functional programming.

Doubly Linked List Overview

In a doubly linked list, each node has a prev reference as well as a next reference. If x.next is y, then y.prev should be x. The reverse link makes it possible to remove a known node without first searching for its predecessor.

The tradeoff is extra space and extra update responsibility. Inserting or deleting a node must repair both the forward and backward links. A bug in either direction can leave the list inconsistent.

Common Pitfalls

Most linked-list mistakes come from losing a reference, mishandling an end case, or confusing the cost of a local update with the cost of finding the update position.

  • Overwriting links too early: During insertion, set the new node's next before overwriting the predecessor's next.
  • Forgetting the empty-list case: Operations that work on ordinary nodes may fail when head == null.
  • Forgetting the one-node case: Removing the only node should leave both head and tail equal to null when a tail reference is used.
  • Not updating tail: Appending, removing the last node, or removing the only node may require a tail update.
  • Ignoring the predecessor requirement: A singly linked list cannot delete an arbitrary known node in the usual way unless it also knows the predecessor.
  • Ignoring search cost: insertAfter(node) is constant time, but insertAfter(first node storing value) includes a search.
  • Creating accidental cycles: A wrong assignment can make a node point back into the list and cause traversal to loop forever.
  • Using linked lists for heavy indexed access: Repeated calls to get(i) can turn into repeated linear scans.
  • Manual memory mistakes: In languages without garbage collection, bypassing a node does not automatically free it.
  • Inconsistent prev links: In a doubly linked list, updating only the forward links leaves reverse traversal broken.

Summary

A linked list stores a sequence in nodes connected by references. A singly linked node stores a value and a next reference. The list stores head, and many implementations also store tail and count.

Linked lists are strong at local reference updates. Inserting at the front, removing from the front, and inserting or deleting after a known node can be constant time. However, finding a node, searching by value, and accessing by index are linear-time operations because the list must follow links.

A tail reference makes appending efficient. A doubly linked list adds a prev reference to each node, which supports reverse traversal and easier deletion of a known node. These improvements cost additional space and require more careful updates.

The main design question is whether the program often already has a reference to the place where the update should occur. If it does, a linked list may be appropriate. If the program mainly needs indexed access or simple scans, an array or dynamic array is often the better representation.
