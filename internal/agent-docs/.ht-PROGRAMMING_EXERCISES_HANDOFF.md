## Repository architecture

DAIADS is a static site. `index.html` loads pages from `Content/` into an
iframe using `?path=` routes. There is no general build system.

Programming-exercise material is organized as parallel trees:

- `Content/Code/`: live downloadable student starters. Do not change or
  promote anything here unless explicitly requested.
- `internal/programming-exercises-v2/Content/Code/`: enhanced candidate
  starters with expanded tests and safe test-only observers.
- `internal/programming-exercise-solutions/Content/Code/`: completed solutions
  copied from v2, with the same relative paths, filenames, public class names,
  helpers, and embedded tests.

Keeping parallel trees avoids Java class/filename collisions, preserves exact
starter APIs, makes relative-file diffs easy, and reduces the risk of shipping
solutions with student downloads. Do not rename solution classes. Do not put a
starter and solution source file in the literal same directory.

Important documentation:

- `internal/programming-exercises-v2/WORK_STATUS.md`: completed test audit.
- `internal/programming-exercises-v2/helper-method-progress.md`: helper-method
  decisions and per-structure summary.
- `internal/programming-exercises-v2/large-input-coverage.md`: all 32 scale
  decisions and assignment order.
- `internal/programming-exercises-v2/problem-text-changes.md`: contract review;
  no live lesson edits are currently required.
- `internal/programming-exercises-v2/README.md`: v2 scope.
- `internal/programming-exercise-solutions/README.md`: solution-tree policy.
- `internal/programming-exercise-solutions/SOLUTION_STATUS.md`: live solution
  checkpoint.
- `internal/programming-exercise-solutions/run_all_tests.py`: recursively
  discovers, compiles, and runs every solution suite in a temporary workspace.

## Completed test work

All 95 v2 files compile or parse. When run against unfinished implementations,
all 95 exit with ordinary failure status; none passes accidentally, crashes, or
times out under the final 30-second audit. The live and v2 trees each contain
95 matching paths and 716 implementation `TODO` markers. No build artifacts
were left in v2.

Large tests are complexity-aware:

- O(1)/linear work generally reaches 100,000 operations.
- The bit-vector set uses a 1,000,000-bit universe.
- Open addressing uses 50,000 keys per probing strategy.
- BST/AVL/2-3-tree workloads use 20,000 keys where appropriate.
- Intentionally quadratic structures retain adversarial 500- or 1,000-item
  tests rather than requiring billions of operations.

Large workloads aggregate results for concise output; smaller tests retain
specific diagnostics. Tests do not generally require zero/negative constructor
behavior. Test-only helpers may expose copies, summaries, or existing metadata,
but must not provide an algorithm students are supposed to implement.

## Solution workflow

Complete exactly one assignment before moving to the next:

1. Copy its complete directory from
   `internal/programming-exercises-v2/Content/Code/<slug>` to
   `internal/programming-exercise-solutions/Content/Code/<slug>`.
2. Implement only the student methods in every available language. Retain the
   v2 tests and helpers unchanged.
3. Compile Java with `javac -Xlint:all`, compile C++17 with `-Wall -Wextra
   -pedantic`, and parse Python with `python3 -m py_compile`. Put all generated
   files under `/tmp`, never in the repository.
4. Run every suite and require exit status 0. Redirect verbose pass output to
   `/tmp` and report a short summary.
5. Update `SOLUTION_STATUS.md`, then proceed to the next assignment.

All 32 solution directories follow this policy, and their full suites passed.
Many include 100,000-operation aggregate tests; workloads
that exercise quadratic behavior use the documented smaller scales, including
the ordinary queue's 1,024-item drain and the unsorted set's 1,000-key
differential test.

After more solutions are complete, add an audit that confirms each solution's
test/support portion still matches its v2 counterpart except for intended
implementation edits. Test duplication is the main maintenance risk of the
parallel-tree design.

## Web protection and security decisions

`internal/` is inside `public_html`. Unix mode `0700` did not protect it:
ordinary internal files were publicly downloadable because Apache had
owner-equivalent access. Adding `internal/.htaccess` with `Require all denied`
also initially failed because production ignored per-directory overrides.

The user subsequently changed Apache configuration. Direct internal files and
the first solution now return HTTP 403, while the public site returns HTTP 200.
Keep `internal/.htaccess` as defense in depth, but do not assume it is the
effective control. Periodically verify a direct file URL, not just a directory
URL. The local server in `internal/testing/.ht-server.py` separately returns
404 for `/DAIADS/internal`.

The GitHub repository is public, so committed internal material may still be
visible there. The user explicitly said this is currently less concerning than
production-site exposure. No files were moved outside the repository.

## Important corrections and failed approaches

- Do not rely on directory permissions or `.htaccess` alone for production
  secrecy; both were empirically insufficient before the Apache change.
- An early ordinary-array queue test incorrectly expected capacity not to be
  reusable after draining. The lesson specifies shifting dequeue, so the test
  was corrected to expect reuse.
- A 200-node chain in the recursive-tree tests originally expected height 200.
  It was corrected to 199 because the contract uses empty height -1 and leaf
  height 0.
- The same recursive-tree suite's irregular nine-node tree expected height 4
  (and 3 for each primary subtree), although its longest root-to-leaf path has
  three edges. The expectations were corrected identically in all v2 and
  solution languages to 3 for the tree and 2 for each primary subtree.
- The recursive-traversal suite's irregular-tree inorder expectation placed a
  node before its left child. It was corrected identically in all v2 and
  solution languages from `20, 40, 20` to `20, 20, 40` at that subtree.
- A first large C++ DFS verifier indexed empty vectors after an unfinished
  implementation failed the size check, causing a signal. Java had the
  analogous risk. Both loops are now guarded, and the final 95-suite audit is
  clean.
- The Python unsorted-array priority-queue test called an undefined
  `check_empty` helper. The helper was added identically to the v2 exercise and
  its solution before verification.
- The Python sorted-array priority-queue test had the same missing
  `check_empty` helper; it was corrected identically in both trees as well.
- The Python 2-3-tree large workload compared the `size` method object with an
  integer. Both assertions were corrected identically in v2 and the solution
  copy to call `size()`.
- Do not blindly use one million items everywhere. Correct quadratic exercises
  would perform impractical billion-operation workloads; follow the documented
  scale policy.

## Working-tree and operational constraints

The repository has extensive intentional uncommitted changes in v2 and the
solution tree. Preserve them. Do not reset, clean, or overwrite unrelated work.
Use `apply_patch` for edits. Mechanical directory copies are acceptable before
patching implementations. Do not leave `.class`, `.pyc`, executables, or
`__pycache__` directories in the repository.

The live `Content/Code/` tree was intentionally left untouched throughout the
test and solution work. Before any eventual promotion, run a fresh 95-file
compile/parse/run audit and review `problem-text-changes.md`.
